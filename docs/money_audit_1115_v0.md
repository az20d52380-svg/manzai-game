## §3 問題なしの確認
1. 支払い額の式：`livingCostDue`（GameEngine.swift:182）は引き落とし（:336）・支払い画面（GameSession.swift:429）・週の一言（WeekMainView.swift:525）・用語集（:1504）・お店の合計（ShopView.swift:81）の全部が同じ関数を使う＝金額が食い違わない。
2. 支払い画面の内訳の和：`RentStatement.breakdown` は端数を最後の行で吸収し、家賃の行に部屋の上乗せを足す＝合計は必ず一致。`moneyBefore = moneyAfter + livingCost`（RentStatement.swift:33-38）。
3. 行動の結果行の収支：`lastMoneyDelta = 週末後 − 行動前 + 払った生活費`（GameSession.swift:430）。押した週の末の state に限っているので、療養週・翌週の分は混ざらない（N1 直し済み）。
4. 用語集の金額：SettingsView.swift:265 は `livingCost`・`livingInterval` から出す＝GameConfig と一致。やりくり上手でも「基本は14万円」と書くのは正しい（基本額）。
5. 中断・再開の二重払い／払い漏れ：`choose`・`decideTournament`・`advanceAuto`・`acknowledgeResult` はどれも pump の後に `saveNow`（:442・:374・:988・:536）。週末処理は pump の中で終わっており、weekClosed も保存される（WeekRunner.swift:655・706）。復元した週に `applyWeekEnd` はもう一度走らない。夜逃げ（finished）も保存される。
6. 年末をまたぐ時：48週の支払いは `choose` で引かれ、年末結果の所持金に入る。次の年の1週目に二重に引かれない。
7. 大会週：出場費は所持金が足りる時だけ引く（WeekRunner.swift:210-214）＝大会で借金は増えない。GP のエントリー費も同じ（:252）。引かれる順は出場費→賞金→週末の生活費で、Python（run_year）と同順。
8. Python 正典との式・順：`applyWeekEnd` ＝ sim_career.py:1135-1142（生活費→生活苦→夜逃げ→解散→誘い）と同順。やりくり上手 140,000×0.95＝133,000（Python は float で 133000.00000000001 になるが乱数・勝敗に無関係）。`tools/check_config_sync.py` は 89/89 一致（実行して確認）。乱数消費はこの経路に無い。
9. 部屋：引っ越しは乱数なし・お金を引かない（GameEngine.swift:186-191）。上乗せは次の月末から。お店の合計行と実際の引き落としは同じ式。ConfigSanity（roomRents 昇順・先頭 0）あり。
