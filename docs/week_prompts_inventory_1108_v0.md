- 変える所：なし。
- 影響：なし。y5w10 のように3組が同時に当たると、プレイヤーが何を先にするか迷う（playtest_mid_1107 の指摘「中」）が残る。

- 影響：すべて表示だけ。GameCore の式・乱数・セーブ形式は触らない（独白の抽選に使う `picker` の「直近に出た文」の記録は、文の候補数を減らすと番号がずれるので、DD の文を差し替える場合は既存の `pick(... scene:)` の候補数が変わる点に注意。テストは DD の候補数を直書きしているものがあれば更新が要る）。
- 工数：小。1目的1コミットで ①②③⑤ を別々に出せる。

### 案③ 場所ごとに役割を決めて、優先順位で最大N個
役割の案（N=3 席：帯／一言行／吹き出し）：
- 帯 = 「いつ（大会まで何週）」と、大会前の経験点の赤帯だけ。ここだけが画面の「唯一の赤」。
- 一言行 = 「いま困っていること」を1つ（お金＞体力＞撮影＞ネタ無し＞予告＞相方）。
- 吹き出し = 雰囲気（雑談・心の声）。警告の話題（残り週・体力・お金）を言わない。
- 札・判子・ゲージ = 事実の表示だけで、文は足さない。
実装：`WeekPromptPlan` のような小さい純関数を WH に足し、帯・一言行・吹き出し・札が「出す／出さない」を同じ入力から決める。吹き出しは、帯や一言行が同じ話題を言う週は雑談/平常の文に置き換える。N は 3 席だが、同時に出る「警告」は最大2（帯の赤帯＋一言行）にする。
- 変える場所：WH（関数追加）、WMV:384-397（吹き出し選び）, 446-486（赤帯）, 1002/1035（札）, 494-523（一言行）、DD:41-76（独白の分岐に引数を足す）。テストは WeekHintTests と DialogueData のテストを増やす。
- 影響：表示だけ。数値不変。ただし分岐が増えて、プレイヤーが「今まで出ていた促しが急に出ない」週が増える。序盤のチュートリアル的な促し（初回の説明 F2）は別枠なので触らない。
- 工数：中〜大。判断（優先順位の最終形）がオーナー決定なので、そこは文書に並べて回答待ち。

### 推奨：案②（①③⑤の二重消し）＋案③の「役割の1文」だけ先に決める
理由：
1. y5w10 の迷いの原因は「同じ話を別の席が繰り返す」ことで、繰り返しを消せば5席が3席程度に減る。優先順位（案③）を作らなくても、まず迷いの大半は取れる。
2. 案②は表示だけで元に戻しやすく、数値・乱数・セーブに触れない（規律Aの外）。
3. 案③の優先順位は「お金と体力のどちらを先にするか」というオーナー判断を含む。候補ブランチがすでに案Bとして一言行の順を出しているので、その採否と合わせて決めるのが自然。
オーナーに聞くのは1問：「赤帯と札、残すのはどちら？」（§3 案②の②）。それ以外は推奨のまま進められる。
