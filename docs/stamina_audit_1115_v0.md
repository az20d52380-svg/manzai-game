1. 新規5件（中1・低4）。体力が0未満・100超になる経路は0（clamp 漏れなし）、Python 正典との式のずれも0（規律A違反なし）。
2. 最も重いのは N1：体調ダウンで倒れた週に、画面が「体力 +N」の緑チップ（火花と音つき）と「キツいバイト　所持金…　体力 +N」の結果行を出す。療養の2週が1回の pump でまとめて進み、3週ぶんの差が「押した行動の結果」として出るため。

## §1 新規の件

### N1 【中】体調ダウンの週に「体力 +N」を祝うチップ・結果行が出る／回復週の生活費が行動の収支に混ざる
- 場所：ManzaiGame/Sources/GameSession.swift:376-423（choose：before を取って pump 後に差を出す）・:1417（pump：weekDone ごとに `phase = runner.begin()` で次週へ自動送り）・:1392（療養週を kaifuku に）／ManzaiGame/Sources/WeekMainView.swift:1273-1279（makeResultLine）・:1356-1362（体力チップ）・:303-307（up チップで火花＋音）・:1284（presentRent は lastLivingPaid だけ見る）。GameCore は WeekRunner.swift:341-347（倒れる）・:437-441（療養週は自動で休むだけ）。
- 起きる手順：体力 30（50 未満）で「キツいバイト」を押す→抽選に当たる→その週は休みに差し替わり、続く療養2週も pump が人の入力なしで一気に進める→止まるのは3週後の自由行動週。`before`（押す前）と `after`（3週後）を引き算するので、例えば体力 30→100（休み60×3で上限）の **lastStaminaDelta=+70**。
  - 結果：「体力 +70」の緑チップ（`up` なので火花と pop 音が鳴る）と、結果行「キツいバイト　体力 +70」が出る。倒れた週に、押したバイトの名前と回復量だけが出て、バイト代は入っていない。モーダル「体調ダウン」は一拍後に出る。
  - 所持金：`lastMoneyDelta = after − before + lastLivingPaid` で、`lastLivingPaid` は押した週（actedWeek）の生活費しか足し戻さない。療養の2週に生活費の週（4週ごと）が入ると、その生活費が「行動の収支」として結果行に「所持金 −140,000」のように出る。しかも presentRent（月末の支払いの画面）は押した週の分しか出ないので、療養中に払った生活費は画面が1回も出ない（借金の段の知らせだけは maybeShowDebtNotice が拾う）。
- 既出か：no（docs の「体調ダウン」「療養」を grep。number_display_audit_1115 は相性チップ・「−0」のみ。save_restore #5 は知らせの見せ済みの件で別）。
- 直し方の案：①療養を含む pump の結果の時（`results` に「体調ダウン」がある週）は、チップ・結果行を出さず（またはモーダルだけ）にする＝表示のみ・GameCore 不変。②`lastStaminaDelta`・`lastMoneyDelta`・`lastLivingPaid` を「押した週の weekDone を受けた時点」で確定させ、療養の週は含めない（pump の最初の weekDone で state を控える）。③療養中の生活費の週にも支払いの画面を出す（①②と別に判断が要る：3連続で画面が出る）。推奨は②（数字が全部「押した週だけ」に揃う）＋チップは体力が下がった時のみ…ではなく「倒れた週は出さない」①。

### N2 【低】療養中の独白（DialogueData の recovering 8行前後・innerVoice の最優先枝）は実プレイで到達しない
- 場所：ManzaiGame/Sources/DialogueData.swift:44-46・:95（recovering）。到達条件の GameCore 側：WeekRunner.swift:436-441（`state.recoveryWeeks > 0` なら自由行動を返さず自動で休む）。
- 起きること：独白は自由行動週（freeAction）の週メインでしか呼ばれない。freeAction を返す箇所は recoveryWeeks==0 の時だけなので、`state.recoveryWeeks > 0` で独白が引かれる場面がない（テスト InnerVoice1026Tests:28 は state を直接 2 にして呼ぶだけ）。大会に出た療養週は週数が減らないが、その週は大会の画面で、次の自由行動週の前に療養の週が自動で消化される。
- 影響：「療養中は全てに優先」という設計意図（Fable13§2）の文が、プレイヤーには一度も見えない。表示漏れではなく枝が死んでいるだけ。
- 直し方の案：①そのまま（コメントで「到達しない」と書く）②消す（配列の採点済み1行は docs に残す）③療養の週を自動で流さず、週メインに「療養中」の週を1拍見せる（仕様変更・判断が要る＝N1 の②③と一緒に）。

### N3 【低】体力の「線」が画面ごとにばらばら（20／25／30／40／50）＋色が出ない画面がある
- 場所と値（§4 の表を参照）：稽古ゲート 20（GameConfig.staminaGate）／独白「体がもたない」25（DialogueData.swift:47・直書き）／週の一言「体力が少ない」≤30（WeekHint.swift:31,49・**≤**）／判定の語り・満身創痍トロフィー <30（JudgeTalk.swift:226,471,476・Meta.swift:172）／ゲージの赤 ≤40（WeekMainView.swift:1410・StageViews.swift:199,335 の3か所・直書き）／体調ダウン抽選と一言「無理すると倒れる」<50（GameConfig.injuryThreshold）／ゲージ3段（振動・明滅）20・50（WeekMainView.swift:1434-1438）。Theme.swift:62-63 の注釈は「警告<50・黄／危険<20・赤」だが、実際の赤は ≤40。
- 食い違い：(a) ちょうど体力 30 で、週の一言は「体力が少ない」（≤30）なのに、判定の語りは「疲れていない」（<30）。(b) ゲージの赤は ≤40 で、どの規則の線とも合わない（ゲートは20、体調ダウン線は50、黄赤の注釈は20）＝赤いのに稽古は押せ、体調ダウンの抽選が 40→5%（体力40）の帯で始まるのに赤が 40 を超えて 41〜49 は緑のまま抽選される。(c) ChoiceEventOverlay.swift:101 と ShopView.swift:20 のゲージは staminaColor を渡さず常に緑（体力 10 でも緑）。
- 影響：数字の表示と規則が一致しない。実害は小（確率や合否には影響しない）。
- 直し方の案：①赤の線を GameConfig 由来の1か所にまとめる（20 か 50 か＝判断：赤＝稽古できない／赤＝体調ダウンの帯のどちらを意味させるか）。②週の一言の ≤30 を <30 に（独白25と合わせるかも判断）。③(c) の2画面にも同じ色関数を渡す。「判断が要る」のは①の線。

### N4 【低】低体力で本番の点が引かれること（<50 で −5／<30 で −10／<10 で −15）が、どの画面の文にも出ない
- 場所：GameConfig.swift:355（staminaPenalties）・GameEngine.swift:259-263（perform）／説明の文：SettingsView.swift:247（「低いと稽古ができず、体調を崩して休むことがある」）・StageViews.swift:174-177（「体力：大会に出るのにも使う。0のまま出ることもできる」）・入口の赤札は体力 0 のみ（:202-204,:307）。
- 起きること：体力 45 で大会に出ても、入口に何も出ない（−5）。体力 5 でも出ない（−15・体力0だけ「体力が尽きた状態で出る」）。
- 既出か：一部。entry_audit_1115_v0 の E1（夜行バスの体力の減りが減点に先に効くのに入口は「体力を使う」だけ）は同じ根の別面。※％の数字は出さない方針（no-win-percentage）と、点の減点の有無を言葉で伝えるかは別の判断。
- 直し方の案：①そのまま（隠し要素にする）②設定の用語に「体力が低いと本番で点が下がる」の1文だけ足す（数字なし）③入口の赤札の線を体力 0 から 30 未満に広げる（判断：どこから札を出すか＝N3 の線と一緒に）。

### N5 【低】倒れて休みに差し替わった週も、キツいバイトが jobCount に数えられる
- 場所：ManzaiGame/Sources/GameSession.swift:390（`if case .job = action { jobCount += 1 }` が resolveAction より前）・:693（`jobCount >= 3` が選択肢イベント regularEmployment の条件）。
- 起きること：体調ダウン（キツいバイトを選んで倒れた週）に、実際は働いていないのにバイト回数が +1。稽古側は `lastTrainingDone == nil` を見て ネタ合わせの数え・trophy・categoryLog を直している（:395-399）が、バイト側には同じ補正が無い。
- 影響：バイトを3回重ねた時の発火が最大1回早くなる程度（UI 層のみ・golden 非対象）。
- 直し方の案：`runner.snapshot().weekResults` ではなく、pump 後に `categoryLog[week] == .kaifuku` かどうか（または「体調ダウン」が results にあるか）で jobCount を戻す。判断は不要（直すなら稽古側と同じ形）。

## §3 問題なしの確認（1行ずつ）
- 体力の変化は全て `GameEngine.add(.体力)` の clamp(0,100)（GameEngine.swift:53）か ChoiceEventEffect.swift:31 の max/min 経由。直接代入は年初の全回復（WeekRunner.swift:132）と DEBUG（RootView）だけ。0未満・100超になる経路なし。
- 体力が動く箇所は稽古・バイト・休み・オファー・夜行バス・飲みの誘い（行く）・生活苦・選択肢イベント・ドリンク系アイテムで、全部 clamp を通る（grep 済み）。
- 稽古のゲート（体力<20）は resolveAction で強制（WeekRunner.swift:332-334）＋UI のグレー（WeekMainView.swift:917・:986）が同じ `config.staminaGate`＝直書きなし。ゲートで休みに差し替えた後は risky が false になり体調ダウン抽選に入らない（Python と同じ順）。
- 体調ダウン：抽選の式 `(閾値−体力)×0.005×喉ケア×体が資本`・療養3週（倒れた週＋2週）・メンタル−5・乱数1回の消費順は sim_career.py:1058-1066 と一致。療養の週は回数券を使わない（A-10）も両方に同じ。
- 体力の定数（稽古・バイト・オファー・休み・温泉・銭湯・ドリンク・夜行バス・飲みの誘い・生活苦の −10・staminaPenalties・injury 4定数・特技 0.7・喉ケア 0.5・部屋の回復）は tools/balance_sim.py／sim_career.py と一致（目視で全突き合わせ・規律A違反0）。
- 選択肢イベントの体力条件（≥80／≥40／≥40／<50／≥15）と sim_career.py:282-295・421・488 が一致。
- 体調ダウンの知らせ：倒れた週に pump が見つけて `injuryNoticeWeeks` を積み（GameSession.swift:1391）、次の自由行動週の週メイン（WeekMainView.swift:1470）または療養明けが大会の入口に重なった週の入口（StageViews.swift:236）で1回だけ出る。両方とも `clearInjuryNotice`。
- 日程表：「体調ダウン」「療養」の両方の週が kaifuku（回）になる（:1392）。出来事ログは「休」で、YearResultView.isRestOnly が埋め草にしない（LogRoundTrip1026Tests で確認される形）。
- 療養の週に人が押せる行動：なし（自由行動を返さない）。お店・能力アップも自由行動週にしか開けない。
- t15（満身創痍）：GP の回戦・敗者復活を通った時の体力 <30（Meta.swift:172）。説明文「体力が少ない状態で回戦を通る」と一致（「<30」を文に出さないのは意図どおり）。
- 体力のゲージ表示は `Int(stamina.rounded())`。体力は整数刻みしか生じない（全加減が整数）ので内部値と表示は食い違わない。休む画面「体力は満タン」は ≥99.5（上限100のみ・問題なし）。
- 文の数字：StageViews.swift:174 の夜行バス「体力を25使う」は `cal.busTravel` から読む＝設定と一致。SettingsView の体力の文に数字の直書きなし。
