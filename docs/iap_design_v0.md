# 課金の設計案 v0（2026-10-19・決めない／案と推奨・コード変更なし）

> 前提（オーナー決定）：基本無料・広告あり。課金は①広告カット ②事務所選び（2周目以降・リリース後アップデート可）③舞台衣装（見た目だけ・周回をまたいで残る）。1周目の事務所は「吉竹興行」。画面に％・勝率は出さない。アプリ名・広告会社・プライバシーポリシーURLは未定（`store_listing_draft_v0.md` §7・§8）。
> 値段はすべて【仮】。Apple の価格帯（日本の円）から発売時に選ぶ。

## §0 要点3行
1. 3つとも**買い切り（非消耗型）**。消耗型（使うと減る品）は作らない＝復元が単純で、ショップの原則「能力に効く品は売らない」とも衝突しない。
2. 値段の推奨は 広告カット 480円／事務所選び 480円／衣装 1着 120円・3着セット 320円。能力に効かない品だけなので安めに揃え、まず買ってもらう形。
3. 作れる所（購入の土台・復元・.storekit テスト・衣装の差し替え口）は決めなくても進められる。値段・セット構成・広告会社だけオーナー判断。

## §1 3つの商品
共通：StoreKit 2 の `Product.products(for:)` で取得→`purchase()`→`Transaction.updates` を起動時から監視→`Transaction.currentEntitlements` で所有判定。画面に「購入を復元」ボタンを置く（審査で必須。中身は `AppStore.sync()` 後に entitlements を読み直す。起動時に自動で呼ばない＝Apple ID のパスワード入力が出るため）。商品ID案：`adfree` / `office_choice` / `costume_<名前>`（全部 非消耗型）。

### 1-1 広告カット
- 種別：買い切り・非消耗型。購入で広告を全て非表示（バナーは元から使わない案＝区切りの所だけ出す、§7 参照）。
- 値段案：安 250円／**推奨 480円**／高 800円。根拠：広告削除課金の相場は 250〜600円帯が多い印象だが、**出典で裏が取れていない**（§2）。カイロソフトの本体売り切りが600円（開店デパート日記2）なので、広告だけ消すのに600円以上は割高に見える→480円以下が無難。800円は旧案「買い切り800円」の再来で、無料アプリの課金としては高い。 → 1,000円・衣装1着付き（オーナー 10/20）
- 注意：広告SDKを入れる＝プライバシー申告が「収集なし」でなくなる（`store_listing_draft_v0.md` §6・§7）。広告会社の決定後に更新。

### 1-2 事務所選び
- 種別：買い切り・非消耗型 1本（4事務所まとめて解放）。2周目以降の事務所選択画面が開く。**1周目は吉竹興行固定**（無料・課金の有無に関係なし）。
- 中身：`agency_options_v0.md` §2 の4種（大手／中堅／小さいが自由／東京の劇場系）。違いはお金・出番・文章の横差だけで能力の縦差なし＝P2Wに当たらない（`office_choice_v0.md` §4）。**式に効くので規律A（実測）が要る**＝実装前に別途測る。
- 値段案：安 360円／**推奨 480円**／高 720円。根拠：遊びの幅が増える「機能解放」型で、広告カットと同格〜やや上。リリース後アップデートなので、発売時に値段を決めなくてよい。
- 懸念：「周回で解放」の案（無料）との二択。課金にするなら、2周目に入って初めて価値が見える＝買う前に何が選べるかを見せる画面（ロック表示つき一覧）が要る。

### 1-3 舞台衣装
- 種別：買い切り・非消耗型。1着ごとに商品を分ける（`costume_<名前>`）。所有は Apple 側の購入記録が正＝**周回（ゲームのセーブ）とは別管理**なので、周回リセットしても残る。復元で他端末にも戻る。
- 効果なし（見た目だけ）。能力・乱数・点数に触らない。
- 値段案：安 1着 80円・セット 240円／**推奨 1着 120円・3着セット 320円**／高 1着 240円・セット 600円。根拠：Apple の最小帯に近く衝動買いしやすい。見た目だけなので、高くすると「ただの飾りに高い」と感じられやすい。セットは単品3つ分より少し安くして「まとめ買い」を誘う。
- 種類（案、決めるのはオーナー）：紋付袴／派手なスーツ／ご当地ハッピ／ヒョウ柄、など。二人の組み合わせ（俺＝青系・谷口＝赤系の既定色を衣装で置換）。

## §2 似たジャンルの課金例（Web検索 8回中 6回・結論は「裏が取れた例は少ない」）
正直に書く：検索で「広告削除の価格」「着せ替え衣装の相場」を直接示す出典は見つからなかった。取れた事実だけ。
- **カイロソフト（育成・経営シミュ）**：『開店デパート日記2』iOS/Android は **600円・アプリ内課金なし**の買い切りで配信。→国内の育成シミュは「本体を売り切り・課金なし」が定番。出典：[gamebiz.jp/news/240650](https://gamebiz.jp/news/240650)・[gamebiz.jp/news/238917](https://gamebiz.jp/news/238917)（検索結果の要約から。どちらの記事かの切り分けは未確認）。
- **パワプロアプリ（育成の大手）**：基本無料・アイテム課金制。課金通貨「パワストーン」1個120円、レアガチャ10連で30〜50個＝約3,600〜6,000円。**ガチャ中心で、うちの買い切り方針とは別世界**。出典：[altema.jp/pawapuro](https://altema.jp/pawapuro)。
- **スマホ買い切りの価格感**：『ドラクエVII』1,800円・『魔界村』360円・『マインクラフト』840円（iOS）、『スーパーマリオラン』1,200円は「ボリューム不足」の声。出典：[moneypost.jp](https://www.moneypost.jp/129023/3/)。→日本のスマホ有料ゲームは数百円台が受け入れられやすく、1,000円超は中身が問われる。
- **取れなかったもの**：広告削除の相場（250/480/600円は私の経験則で出典なし）、衣装の相場。**推奨値段は仮説**として扱い、発売前に App Store で近い国内インディー数本の実価格を目視で確認するのを次の一手にする（調べ物・決めない範囲）。

## §3 実装の手順
### 決めなくても作れる部分（先に進めてよい）
1. `Store/PurchaseManager.swift`（新規）：商品取得・購入・`Transaction.updates` 監視・`currentEntitlements` から「所有ID集合」を作る。ObservableObject で画面に配る。
2. `Configuration.storekit`（Xcode のローカル設定）：3商品（仮ID・仮値段・非消耗型）を登録し、スキームの StoreKit Configuration に指定。Xcode の Transaction Manager で購入・返金・失敗を再現できる。**限界**：アプリを消すと .storekit の購入履歴も消える＝「再インストール後の復元」は実機のサンドボックスで確認（Apple 開発者フォーラムの報告）。
3. 設定画面に「購入を復元」ボタン（失敗時の文言も）。
4. 衣装の差し替え口：舞台の二人は `StageFrame.swift` の `duo()` が `ManzaiFigure(bodyColors:, accent:, headColor:, hairColor:)` の**色の引数**で衣装色を決めている（`grep` で確認。専用の衣装型はまだ無い）。`CharacterAvatars.swift` にも似た描画がある。→ `enum StageOutfit { case standard, … }` を作り、`bodyColors/accent` を返すだけの小さな関数にして `duo()` の直書き色（青 4A7BE8/2E55B0・赤 F0533E/C22E1D、`rival` 時は別色）をそこへ置換する。**GameCore・乱数・点数に非接触**。形まで変える衣装（袴など）は `ManzaiFigure` 側に追加の図形が要る＝絵の発注が前提（`art_order_sheet_v0.md`）。
5. 選んだ衣装の保存：所有は StoreKit が正、**「どれを着ているか」だけ** UserDefaults（セーブとは別キー＝周回リセットで消さない）。
6. 広告の差し込み口を抽象化（`AdProvider` プロトコル＋「何も出さない」実装）。所有ID に `adfree` があれば呼ばない。広告会社が決まるまでは空実装。
7. 申告の更新：StoreKit を足した時点で `store_listing_draft_v0.md` §5・§6 を更新。

### オーナーの判断が要る部分
- 広告の会社・プライバシーポリシーURL（未定）→広告SDKの実装と ATT 要否はここに依存。
- 値段（§1）、衣装の種類と最初の数、セット構成。
- 事務所選びを課金にするか、周回解放にするか（`office_choice_v0.md` §4）。
- アプリ名・開発者名（App Store Connect の商品登録に必要）。

### 順序の案
(a) PurchaseManager＋.storekit＋復元ボタン→(b) 衣装の色差し替え口（standard のみで見た目不変を確認）→(c) 衣装を1〜2着追加して目視→(d) 広告枠の抽象化→(e) 広告会社決定後に SDK→(f) 事務所選び（実測後・リリース後アップデート）。

## §4 オーナーに聞くこと（最大4問）
1. **何を決めたい**：広告カットの値段。推奨：480円。理由：本体売り切りの国内育成シミュ（600円）より安く、衝動で買える水準。
2. **何を決めたい**：事務所選びを「お金で買う」か「周回で無料解放」か。推奨：買う（480円・リリース後アップデート）。理由：決定済みの課金の柱の一つで、能力の差がないので「ずるい」にならない。
3. **何を決めたい**：衣装を最初に何着、どう売るか。推奨：発売時は2〜3着を1着120円＋3着セット320円。理由：絵の発注と目視の手間を小さく始め、売れ行きを見て足せる。
4. **何を決めたい**：広告の出し方と会社（広告会社・プライバシーポリシーURLも未定）。推奨：区切りの所（年の幕間・結果画面）だけ・決勝の最中は出さない。会社選びは発売準備の後半でよい。理由：山場に広告が出ると世界観と没入が壊れ、広告カットも買いたくなくなる。
