# 経験点システム パワプロ式5通貨 再設計 v0（正典v3・2026-08-02）

## 0. 何が変わったか（一行）

**旧**: 5能力（センス/発想/表現/華/メンタル）にそれぞれ専用の経験点バンクがあり、稽古はそのまま該当能力のバンクに積まれる（実質1:1、共通枠ρは0で休眠）。
**新**: 能力名と別立ての**5経験点通貨**（閃き/語彙/間合い/存在感/胆力）を稽古が発行し、各能力は**複数通貨の重み付きブレンド（レシピ）**で伸びる。1通貨は複数能力に、1能力は複数通貨に依存する**真の多対多**。

## 1. Webリサーチで裏取りした実機仕様（要点）

- 「経験点」（筋力・敏捷・技術・変化球・精神）は攻略サイトで広く確認できる実在システム。1回の練習で**必ず複数種類が同時に増加**（例: 打撃練習＝筋力+10／技術+16／精神+6）。
- 能力アップは**基本的に複数種類の経験点を同時消費**する設計（例: ミートは筋力・技術・精神の3種）。
- 「能力アップ検」という名称・提示された具体数値の一次資料は確認できなかった（用語の出典不明）が、**構造（多対多）自体は複数ソースで裏付けられた**。
- 詳細は調査agentレポート参照（本セッションのscratchpadに保存・要点は上記）。

## 2. 新設計: 5通貨×5能力の重み付きレシピ（Leontief固定比率）

### 2-1. 通貨（能力名と意図的に別語彙）

| 通貨 | 由来のイメージ |
|---|---|
| 閃き | アイデアの瞬発力 |
| 語彙 | 言葉の引き出し |
| 間合い | 間・テンポ |
| 存在感 | 華・舞台映え |
| 胆力 | メンタルの土台 |

### 2-2. 能力→通貨レシピ（`GameConfig.abilityRecipes`・全て【仮】）

| 能力 | レシピ |
|---|---|
| センス | 閃45% + 間35% + 胆20% |
| 発想 | 閃65% + 語35% |
| 表現 | 語35% + 間65% |
| 華 | 存70% + 閃30% |
| メンタル | 存25% + 胆75% |

設計方針: 各通貨は最低2能力に、各能力は最低2通貨に依存（全表で充足）。`AllocationTests.testRecipeIsGenuineManyToMany` が構造を固定。

### 2-3. 稽古→通貨（`GameConfig.trainings`・main/subは`.currency`タグ）

| 稽古 | main | sub |
|---|---|---|
| ネタ作り | 閃き+3 | 語彙+1 |
| ネタ見せ会 | 間合い+6 | 胆力+3 |
| ネタ合わせ | 間合い+3 | 相性+1（経済外・不変） |
| ランニング・サウナ | 胆力+6 | — |
| フリーライブ | 存在感+3 | 間合い+1 |

量は旧版（能力直付け）を踏襲＝`expSupplyScale=0.48`等の既存較正値を出発点にできる。

## 3. 機構（pourStep のボトルネック方式）

`add()`（①逓減→②予算→③clamp）は**無改修**——通貨変換とは独立。変わったのは「どれだけ能力に注ぎ込めるか」の計算だけ：

```
affordableRaw(a) = min(allocationStep, min over (currency, weight) in recipe of balance[currency] / weight)
```

最も乏しい通貨がボトルネック（Leontief固定比率＝料理のレシピと同じ「材料が1つでも欠けたら作れない」）。実際に使った分だけ、レシピの全通貨を同じ比率で同時消費する。

- `recommendedPlan`: 旧「ロック→共通枠」2段ループを廃し、**注げる能力の中で現在値が最も低いもの**へ毎ステップ回す単一の追いつきループに一般化。
- `pourable(_:config:)`: UI互換のため残置（旧シグネチャから `config:` 必須に変更）。

## 4. 動作検証（12週ローテーションsim）

全5種の稽古を順番に回すと、5能力すべてが伸びる（特定稽古だけへの偏りは対応能力の成長を止めるが、永久凍結はしない）。特化と汎用のトレードオフが機能していることを確認済み（Python smoke test）。

## 7. 今後の課題（sim較正・別便）

- レシピ重み・稽古発行量は全て【仮】。`tools/sim_career.py`で複数戦略ボットを回し、到達率帯（旧: やり込み44.5/のんびり23.1/バランス9.1）が壊れていないか要実測。
