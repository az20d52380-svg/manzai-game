# 審査員の点・投票・講評 v0（2026-10-20 オーナー決定への対応案）

**オーナー決定(10/20)**：審査員ごとの点数・投票・講評は「能力」と「ネタの完成度」の割合で変わる。全能力MAXなら全員投票して優勝でもよい。ネタの「型」（しゃべくり・コント漫才）はなくす。
**状態**：調査＋案のみ。コードは触っていない。数値は全て【仮】。決めるのはオーナー。

## §1 今の作り（勝敗の決まり方）
- 予選〜決勝の合否は `GameEngine.perform`（GameEngine.swift:239）の1本で決まる。
  `score = jitsuryoku(センス0.30＋発想0.30＋表現0.25＋華0.15) ＋ compat ＋ roll(±ブレ幅、メンタルで5〜20) ＋ ハマった夜(10%で+12) ＋ 体力ペナルティ` が `line` 以上なら通過。
- ライン側にネタが乗る：`line − netaScoreBonus`。bonus＝`(polish−50)×0.04＋(buzz−50)×0.02`を±5に丸め、飽きの減点、決勝は2本目が無い/polish<60で−3（GameEngine.swift:263）。**型は一切入らない**。
- 決勝はさらに `ライン − 1.5×(知名度−50)/50`（WeekRunner.swift:262）。呼び出しは WeekRunner の3か所（大会週・GP回戦/敗者復活・決勝）。
- 乱数は perform で常に2draw固定（gen_golden.py の正典順）。netaScoreBonus は乱数を取らない。Python 正典は tools/sim_career.py（`_neta_bonus`）。
- 結論：**勝敗は「合計点とライン＋乱数1個」。審査員は登場しない。**

## §2 審査員ごとの点・最終決戦の投票（FinalsData、ManzaiGame/Sources/FinalsPresentationView.swift:1170〜）
- 完全に**表示用の後付け**。GameCore は margin（スコア−実効ライン）と champion(真偽)だけを渡す。
- 順位：champion/margin から自組の1本目順位を決める（margin≧8→1位、≧3→1〜2位…。負けは4〜10位）。表示合計Sはその順位に合わせた帯内の乱数（優勝632〜668/700）。
- 7審査員の点：`S/7 ＋ 人格bias(−2〜+2) ＋ tilt(重視軸) ＋ ノイズ(±1〜3)`、tilt＝(重視軸の能力−4能力平均)/10を±3に丸め。重視軸は 音羽=華／白波=表現／卯月=発想／花園=compat／目白=発想／神楽坂=メンタル／天堂寺=センス。最後にΣ=S になるよう±1ずつ補正。**「ネタの完成度」は点に入っていない**（講評の語だけ）。
- 最終決戦：上位3組・7票。優勝者は先に決めてしまう（優勝なら自組、負けなら他組を1本目順位で重み付け抽選）。票数は勝者 w票(4〜7、margin≧20で6〜7)、残りを乱数で割り、voteOrder をシャッフル。**審査員ごとの好みは票に無関係**（7票は審査員に紐付かない、めくる順が乱数なだけ）。
- 乱数：UI専用 SeededRng（能力・年で決定的seed）。**GameCore の乱数列は消費しない**＝golden 非干渉。
- つまり今は「勝敗(GameCore)→見せ札(FinalsData)」の一方向で、見せ札は勝敗に合わせて作られる。食い違いは構造上起きないが、審査員の個性は点にも票にも実質出ていない。
- 7審査員の好み：docs/judge_design_v0.md §10-F（ウケ量60〜80%＋技術/華/人気/関係性の重み表・議論中）、型×審査員の「◎○△×」表は NetaCatalog.affinity（表示のみ・合否非干渉と明記）。

## §3 講評の言葉が何で変わるか（GameCore/JudgeTalk.swift、647行）
- 帯（E/D/C/B/A＝表示点で決定）×審査員×最高点か最低点か（`high`）。
- 場面フック（Scene）：ネタ題・**型(kata)**・鉄板・寝かせた再演・おろしたて・ハマった夜・出順/大トリ・敗者復活経由・compat/体力/メンタル/華。予選の紙講評は margin（惜しさ）。
- **型の使われ方**：語彙表（`.王道しゃべくり`など7型×入り/中/一言/締め、JudgeTalk.swift:79〜、nil＝型なし用あり）で講評に具体物を差し込む。型が無い時は型なし語彙表に落ちる設計＝**型を消しても講評は崩れない**。
- 能力は hana/compat/stamina/mental の閾値フックだけ。**完成度(polish/buzz)は講評に使われていない**。
- 乱数は salt の剰余（決定的）。GameCore非干渉。

## §4 案（審査員の点と票を「能力の割合」×「ネタの完成度」で決める）
共通の部品：審査員 j ごとに重みベクトル `w_j`（センス/発想/表現/華/相性/完成度の6項、行合計1）を決める。たたき台は judge_design_v0 §10-F の表を能力軸に読み替え（例：天堂寺＝センス重・完成度中、白波＝表現＋華、音羽＝華＋知名度、花園＝相性、卯月/目白＝発想＋完成度、神楽坂＝メンタル/話芸）。個人点 `p_j = 50＋k×(Σ w_j,i × 項目_i − 基準)`、50〜99クランプ。完成度 c は選んだネタの `polish`（必要なら buzz を少し足す）。

### 案A：表示だけ（勝敗は今の式のまま。規律A不要）
- 勝敗・margin・Sは今のまま。S/7 を土台に、各審査員の点を `S/7 ＋ (p_j − 平均p)` で決める（Σ=Sの補正は今のまま）。ノイズは今の小さな±のまま。
- 票：決勝3組それぞれに審査員ごとの個人点を作る（自組＝上の p_j。他組＝その組の合計Sから審査員ごとの偏りで生成。偏りは組ごとにseed固定）。各審査員は個人点が最高の組に投票。
- 食い違い防止：①champion なら自組が最低4票になるまで「自組との差が小さい審査員」から1人ずつ自組に倒す、負けなら自組が過半数にならないよう逆に倒す（今の「勝者先決め」と同じ保証を残す）。②点→票の順で作り、保証は最後の補正1段だけ。
- 「全能力MAXなら全員投票」：成立する。MAXの時は p_j が全員NPCの個人点（合計上限約650/700のNPC）を上回り7-0になる（補正は発動しない）。今は最大7票でも「margin≧20のとき6〜7を乱数で」なので、ここを「個人点の比較の結果」に置き換えるだけ。
- 長所：golden/規律A不要・本編乱数は触らない。短所：能力が低くても勝てば1〜2人は自組に倒す補正が入る＝「点と票が能力割合だけで決まる」わけではない（補正分は説明がつくよう最小に）。

### 案B：勝敗そのものを審査員ごとの点の合計にする
- B1（線形）：`w_j` を「7人の平均が今の全体重み(0.30/0.30/0.25/0.15＋相性)」になるよう組む。すると Σ個人点＝今の jitsuryoku＋compat と**数学的に同じ**で、勝敗は変わらず、点・票・講評が能力割合で変わる。完成度は line の bonus と同じ係数で個人点に配るだけ（決勝の2本目減点・知名度補正も7人に等分）。乱数は今の2drawのまま＝**golden・既存実測は不変の見込み**（一致をテストで確認すれば足りる）。
- B2（非線形）：審査員ごとに通過/不通過を出し「過半数が通す」で合否にする、あるいは審査員ごとに個別ライン・個別ブレを持たせる。これは勝率が動く＝規律A、`gen_golden.py` 再生成、実測（n=300→1000）、WeekRunner/Python 両方の式変更が要る。審査員別ブレにするなら乱数のdraw数が増え、golden 全体が変わる。
- 「全能力MAXなら全員投票」：B1は成立（MAXは全員のしきい値を超える）。B2は個別ブレがあると1人くらい外れる設計も可（全員一致を保証したいなら個別ブレをMAXで0にする）。
- 食い違い防止：B1は構造的に一致（同じ式の分解）。B2は「合否＝審査員点の合計/過半数」と票を同じ関数から出すので一致するが、perform を使う全呼び出し（予選・敗者復活・決勝）と Python 正典を同時に直す必要がある。

### 推奨（1行）
**案Aの形でまず入れ、点の割り振りは B1（平均が今の重みになる線形分解）で作る**＝規律A・golden再生成は不要で、能力割合×完成度が点・票に出て、MAX＝7票も成立。B2は「審査員ごとに勝敗が割れる」手応えが欲しいと決めたら、別枠で実測してから。
