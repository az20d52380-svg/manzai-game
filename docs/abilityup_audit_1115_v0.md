## §1 指摘

### 1. 特技を覚えると、まだ確定していない＋の分が黙って確定される（中・確信 高・既出なし）
- 場所：AbilityUpView.swift:116（`if !taps.isEmpty { _ = session.allocate(taps); taps.removeAll() }` の後に learnSkill）。ダイアログ文は「「◯◯」を覚える？」だけ（:108）。
- 手順：＋を数回押す（未確定）→ 画面下の特技の札を押す →「覚える」。
- 見えること：「覚える？」の確認だけ。実際に起きること：押した段が全部その場で確定・保存され（saveNow）、画面の taps は空になる。その後に「戻る」を押しても能力は戻らず、「確定せずに閉じたら何も変わらない」が崩れる。経験点が特技代と競合するのでプレビューの pv は正しく、金額の誤差は無い（確定の順序＝先に能力→次に特技で、canLearn は pv と同じ状態を見ている）。
- 最小の直し：ダイアログのタイトル／メッセージに「押した分の能力アップも一緒に確定します」を足す（文字だけ）。あるいは taps が空でない時だけ文を変える。

### 2. 「−」は押すとその能力の全段が戻る／おまかせ後の端数段は「−」で戻せない（低・確信 高・既出なし）
- 場所：:293（`taps.removeAll { $0 == a }`）、:279 と :321（canUndo＝表示整数が上がった行だけ）。
- 手順：センスの＋を3回押す→「−」1回 → 3つ全部戻る（1つずつ戻らない）。おまかせ→表示整数の上がっていない能力（端数だけ注いだ行）は「−」が灰色で押せず、リセットでしか戻せない。
- 実際に起きること：ラベルは「元に戻す」だけ。通貨を共有する別の能力（閃き＝センス・発想・華）の最後の端数段は、戻した分の通貨が空くので次の再生で少し多く伸びる＝他の行の数字が動くことがある（確定は表示と一致するので誤りではない）。
- 最小の直し：行単位で全部戻すのが意図なら読み上げラベルを「◯◯の＋を全部戻す」に。1段ずつなら `taps.lastIndex(of: a)` の1つだけ消す。

### 3. 確定ボタンの「+N段階」は内部の段数で、表の「+1」と単位が違う（低・確信 高・既出なし）
- 場所：:439（`"+\(taps.count)段階"`）。＋1タップは複数段（逓減・等級で2〜十数段）を積むので、＋を3回押すと「+9段階」等になる。おまかせだと数十段。
- 実際に起きること：確定で上がる能力ポイントの数（表の「アップ後」）と一致せず、「9も上がる？」と読める恐れ。直した場合の数字は壊れない。
- 最小の直し：「+N」を使わず上がる能力の表示整数の増分合計（`Σ gained`）を出す、または「段階」を外す。

### 4. おまかせが表示の上がらない端数段も確定して経験点を使う（低・確信 中・既出なし）
- 場所：GameSession.swift:540〜556（延長ループは `pourStep > eps` なら足す）。pourStep は見える伸びが 1e-9 超なら通貨を引くので、端数だけの段（例 29.0→29.3）も確定対象になる。
- 実際に起きること：確定後に経験点が空になるが、表示整数が上がらない能力の分は目に見えず「使ったのに増えない」ように感じる場合がある（端数は内部に残り次の＋で効く＝損ではない）。
- 最小の直し：現状維持が妥当（端数が次の+1に繰り越る）。直すなら画面に「端数も使う」の一文。

### 5. 持ち分（切り捨て）と値札（切り上げ）の丸めで、「持ち分−値札」が実際の残りと±1ずれることがある（低・確信 中・既出なし）
- 場所：:515〜527 ExpDisplay（value＝切り捨て、cost＝切り上げ）、:275〜283 nextPlusOne。
- 例（内部値で手計算）：持ち分 1.05（表示10）・値札の実消費 0.315（表示4）→ 引いた後は 0.735（表示7）。10−4＝6 と7でずれる。内部が0.1刻みでない（重み0.35・0.7倍等）ので起きうる。
- 実際に起きること：実際に引かれる量は値札の内部値（d）で、確定結果は常にプレビューと一致。ずれるのは「持ち分の数字−札の数字」の暗算だけ（1点）。
- 最小の直し：不要（既存の注記「14持ち・15必要を出さない」の安全側の丸め）。

## §2 問題なしと確かめた主な所
- 見積もり＝確定の一致：プレビュー（previewAllocation）と確定（applyAllocation）は同じ `GameEngine.pourStep` を同じ順で回す純関数。session.state と runner.state は allocate 直前まで同じ（state=runner.state が18か所で同期）。見積もりと確定の式の複製なし（projectedGain は add と同値＝AllocationTests.testProjectedGainMatchesAdd）。
- ＋1回＝costOfNextStep が数えた n 段分を taps に足す（plusTap）。連打しても毎回その時点の pv で n を再計算するので、通貨・器・等級が途中で変わっても段数が合う。
- 複数通貨：Leontief（最も乏しい通貨で決まる）。nextPlusOne の値札は pv と＋後の差（d）＝実際に引かれる量そのもの。短い通貨は灰色（n＞持ち分）で、足りると言いながら押せる行は出ない（cost() が持ち分の表示値を超えない保証がある）。
- 等級の境目：rankCostMultiplier は pourStep ごとに現在値で選ぶ＝境目をまたぐ+1の値札は段ごとの合計（シミュレーション）。表示整数の+1に届く段数で止めるのでずれない。
- 上限：costOfNextStep は届かなければ nil（＋が灰色）。clamp は projectedGain と add の両方で同じ。逓減（120）で上限近くは段数が増えるが60段ガードの手前（約118まで）。
- 戻す：リセット／＋行の「−」とも taps を作り直すだけで base（session.state）は不変＝残りが元に戻る。「戻る」は taps を捨てて onClose（allocate を呼ばない）＝確定せず閉じて何も変わらない（特技の経路を除く＝指摘1）。
- 確定の二重押し：confirming／confirmFinished で反映は1回。余韻中の overlay が footer の他ボタン（戻る含む）を止める。余韻中のタップは即 finishConfirm（同じガード）。
- 経験点が足りない時の＋：next==nil なら disabled。部分段（残高が1段に満たない）は affordableRaw が端数を許して通貨を使い切る＝仕様で、値札・確定とも整合。
- 特技の費用：pv（＋済み）の持ち分で canLearn を判定し、確定は allocate→learnSkill の順＝二重に引かない。
- 乱数：Allocation 系は RandomSource 非消費（golden 不変）。
