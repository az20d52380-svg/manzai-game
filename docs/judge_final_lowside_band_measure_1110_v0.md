# 決勝の最低点の審査員がB帯（91〜94点）になる割合の実測（11/10・v0）

## 結論（3行）
- 決勝に出た1000回のうち、最低点の審査員がB帯（91〜94点）になったのは **約1.6%**（16回。優勝した回だけに限ると36〜39%、惜敗・1本目敗退ではほぼ0%）。
- B帯の最低点は「優勝の年（合計632〜668）」でしか起きない＝全体では稀。judge_final_comment_score_v1 §4 論点1の案C（稀なら放置）は材料としては成り立つ。ただし優勝の夜だけに限ると3回に1回強で出る（優勝演出の直後に「最低点なのにB帯」の講評が出る）。
- 最低点の帯は 全体で D 86.7%／C 11.7%／B 1.6%／A 0%。決勝に出る組の大半が1本目敗退（合計560〜630台）で、最低点は80〜85点台。

## 方法
- 点の出し方は UI 側（ManzaiGame/Sources/FinalsPresentationView.swift の FinalsData.init・judgeDeltas・judgeWeights・SeededRng）。**その式を読み書き写して計算した（写し）**。GameCore には無い。実行場所: scratchpad/lowband（GameCore を path 依存にした実行パッケージ・本体は変更なし）。
- 最低点の取り方は commentPicks と同じ（点の降順・同点は並び順の後ろ）＝帯は JudgeTalk.band（A=95〜／B=91〜94／C=87〜90／D=〜86）。
- 入力の幅：GameCore の WeekRunner を runYear と同じ手順で回し、**決勝（.gpFinal）に立った瞬間の能力・相性**を記録。ボット3種（ランダム／稽古重視＋新幹線／安価な稽古＋バイト＋体力で休む）を seed を変えて 15,614 キャリア回し、決勝に立った 1000 回を採取（優勝44・負け956）。決勝の合計点・順位は写した式どおり margin（負けは実測の GP決勝 margin、優勝は margin 不明のため m<8 扱いで rank を引く＝合計は優勝帯632〜668に固定されるので影響なし）から決まる。
- ネタ完成度 polish は 60 固定と 50〜90 一様の2通り（結果はほぼ同じ）。審査員点の乱数は写した SeededRng（能力・年から決まる）。

## 限界
- 決勝に立つ組の構成（優勝44／負け956＝優勝4.4%）はボットの強さで決まる。人間の上手いプレイでは優勝の割合が上がり、B帯の割合も上がる（B帯の割合 ≒ 優勝割合 × 約0.37）。優勝が10%なら約4%、25%でも約9%。
- 優勝時の margin を取れていない（WeekRunner の weekResults が非公開）。合計は優勝帯固定なので審査員点の分布には効かないが、乱数消費の位置は実機と少しずれる。
- 乱数 pool のシャッフル回数は名簿の実数でなく 40 で写した（消費量のずれ）。能力は点の偏り（上限±2.5）にしか効かないため、結論への影響は小さい。
- 実機は p_j の相性・メンタル等が毎回違う。UI の高点・低点が別人になる回の帯は考えていない（最低点の帯のみ）。
