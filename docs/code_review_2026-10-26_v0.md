## §2 中

### 2-1 年末独白：新しい「負けを語る行」が勝ち越し年のフィルタから漏れる
- 場所：`YearResultView.swift:372-376`（`loseLeaning`）と `:403-414`（`yeStall` に今回足した行）。フィルタは `:377-381` の `filterByRecord`。
- 何が起きるか：停滞年（決勝に届かず破産でもない年）の独白は `yeStall` から引く。勝ち数が負け数より多い年は `loseLeaning` の行だけを外す。ところが外す対象は旧3行しかない。今回足した「今年は、うまくいかない日が続いた」「思ったような一年にはならなかった」「今年は、負けて帰る日が多かった」「伸び悩んだ一年だった」「今年は、谷口に心配をかけた一年だった」は入っていない。
  手順：頂GPで3回戦まで通過（勝ち3・負け1）して準決勝で負ける。停滞年に分類され、`filterByRecord` は旧3行しか外さない。salt の当たり方によって「負けて帰る日が多かった」と表示される。
- 直し案：`loseLeaning` に上の5行を足す。行を足すたびに漏れるので、`yeStall` の「負け語り」行に印を付ける形（別配列に分けて `stallLoseLines` とし、`yeStall = stallNeutral + stallLoseLines`）にするとよい。
- 重さ：中（見た目の矛盾が出るだけで進行には影響しない）。

### 2-2 年末独白：出会い方（MeetingKind 4種）と食い違う「高校の同級生」の行
- 場所：`YearResultView.swift:~397`（`yeLeap`）の「高校の同級生から、久しぶりに連絡が来た。年明けに、会いに行こう。」
- 何が起きるか：出会い方を①高校の同級生以外（他3型）で始めても、この行は固定で出る。「高校の同級生」は相方のことではなく別の友人と読めるので、設定との食い違いまでは言えない。ただし独白は一人称で、前後が相方（谷口）の話ばかりなので、相方の出会いが別の型のデータだと読み違えやすい。MeetingKind 側の台詞とも別管理。
- 直し案：「昔の友だちから」に直す（出会い方に依存させない）。
- 重さ：低〜中（読み違えの可能性。推測を含むので確実度は低め）。

## §3 低

### 3-1 `FinalsData.judgeVotes` が書き込まれるだけで誰も読んでいない
- 場所：`FinalsPresentationView.swift:1187`（宣言）・`:1371`（代入）。参照は他に無い（`grep judgeVotes` で2件のみ）。
- 何が起きるか：審査員ごとの投票先を作っているのに、画面は `voteOrder`（シャッフル済みの添字列）で票をめくる。審査員の顔と票の対応が出る画面は無いので害は無いが、「審査員ごとの個人点で投票する」という計算（キュー116）の成果が表に出ない。誰がどの票を入れたかを画面に出すつもりなら未接続。
- 直し案：使うつもりが無ければ削除、あるなら票をめくる所で `judgeVotes` の並び（審査員順）を使う。
- 重さ：低。

### 3-2 優勝の台詞を全コンビ共通の口調に固定している
- 場所：`FinalsPresentationView.swift:~219`（`partnerLine: "「やったね。本当に、日本一だよ」"`）と `:~1125`（`"……本当に、勝ったんだね"`）。
- 何が起きるか：以前の「やったな」「勝ったんだな」から「ね／だよ」に変わった。相方が男の組（男コンビ・自分が女で相方が男）でも柔らかい口調になる。「全員標準語」（ChoiceEventData のコメント）という決定の範囲内ではあるが、`partnerIsFemale` で書き分けていない。
- 直し案：`Names.kind.partnerIsFemale` で分けるか、中立な言い回しにする。
- 重さ：低（文言）。

### 3-3 `Names.show` の「{partner1}ら」置換は相方が「私」の時に誤訳になる形
- 場所：`Names.swift:40-43`。
- 何が起きるか：`("{me}", …), ("{partner1}", …)` を同じ表で回し、`key + "ら"` を「私たち」に置換する。`{partner1}ら` と書かれた台詞があれば、相方が女の時に「私たち」（自分と相方の意味になる）になる。今の `Sources` には `{me}ら` の使用（`ChoiceEventData.swift:345`）しか無く、`{partner1}ら` は存在しないので今は顕在化しない。
- 直し案：`{me}ら` だけをループ外で置換する。
- 重さ：低（潜在）。

### 3-4 「新しく書く」の印はセーブされず、再起動すると勝負ネタを磨く動きに戻る
- 場所：`GameSession.swift:~52`（`writeNewNeta`）、`beginNewWrite()`（`saveNow()` するが `writeNewNeta` はセーブ項目に無い）。
- 何が起きるか：手順：「新しく書く」を選び題名を入れる（まだ書いていない）→アプリを終了→再開すると `writeNetaID=nil`・`writeNewNeta=false` になり、書く対象は勝負ネタに戻る。意図どおり（コメントに明記）だが、画面の「新しく書く」の入力欄は消える。ユーザーが選び直せば済むので問題は小さい。
- 重さ：低（仕様どおり。記録のみ）。

## §4 確認して問題なし
- **二重押し**：`GameSession` の `finishWatchingFinal`（`watchingFinal` ガード）・`advanceAuto`（phase ガード）・`acknowledgeResult`（`pendingResult` ガード）・決断／自由週の `guard case` はいずれも再入しても週が進まない／行が積まれない。
- **復元時の phase**：`sameStep` は大会決断・自由週・回戦だけを新しい config の値に差し替え、`weekDone`／`yearDone` は保存値のまま。差し替えで週や所持金が変わる経路は無い（`restoredPhase = currentPhase()` は runner の状態から作り直すだけ）。
- **セーブの後方互換**：`comboKind`／`meetingKind`／`writeNetaID`／`watchedFinal` はすべて Optional で、旧セーブは男コンビ・①高校の同級生・勝負ネタを磨く動きに落ちる。`stripKeys` 側（`GameSession.swift:~1766`）も `comboKind`／`meetingKind` を追加済みで、旧形式との比較テストは通る形。
- **書く対象ネタ**：`writeTargetID` は、新しく書く指定・書く対象・勝負ネタの順で、消えた（しまった）ネタは `contains` で外す。`retireNeta` が `writeNetaID` を外す。枠満杯の「新しく書く」は最後のネタを改稿して印を下ろす。`WeekMainView.writeTarget` と `GameSession.applyNetaWork` の判定は同じ規則で食い違いなし。
- **夜逃げ・解散の週の記録**：`yearHistory.last?.year != runner.year` のガードの中で、`weekResults` から出来事ログと賞金を1回だけ足す。`weekDone` を経ないので二重計上にならない。
- **`bestRunLine`**：進行中の年の `roundsPassed==0` かつ決勝進出でない場合は追加されず、`names[min(...)-1]` が -1 になる経路は無い。最高成績の同点は早い年を選ぶ。
- **決勝の最終決戦の投票**：自組優勝は最低4票、負けは3票以下かつ首位でない、勝者は4票以上に補正する。各ループは `pick < 0` で脱出するので無限ループにならない。
- **導入フロー**：名前入力→回想の順に変わり、`finish()` は回想完了・スキップのどちらでも1回だけ呼ばれる。`Names.setKind` は新規・復元の両方で呼ばれる。
- **用語集の文言**：「出順抽選：運で決まる」「暫定席：上位3組」「王手：あと1票」は、`FinalsData` の出順乱数（`rng.int(1...10)`）・上位3組・4票で決着（王手＝3票）の実装と一致。
