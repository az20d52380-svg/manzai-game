- **やり込みだけ 300 seed 全部ずれた**。原因は実測スクリプトの穴：やり込みボットは作る時（`exp_stuck_v0.make`）に `B.enable_paid_rests(True)` を呼び、`PAID_RESTS` から温泉を入れ直す。スクリプトは温泉の差し替えを `B.RESTS` にだけ入れていたので、**やり込みボットの温泉はメンタル+2 のまま測られていた**。新正典で `PAID_RESTS` の温泉もメンタル+2 を戻す（＝実測と同じ穴を再現する）と、やり込みも 300 seed 全部ビット一致した。
  - つまり式の写しは実測と完全に同じ。違うのは「温泉＝体力回復だけ」がやり込みボットにも効くようになった分だけ（オーナー決定どおり）。その分の数字の動きは下の「段1 の後の数字」に書く。

### 細部の決め
- **11年目以降の決勝・敗者復活 +2**：実測スクリプトは `GP_FINAL_LINE` を年ごとに書き換えていた。正典では `GP_LATE_START_YEAR=11`・`GP_LATE_LINE_BONUS=2.0` を足し、`run_year` の中で決勝 `GP_FINAL_LINE + late`、復活 `GP_REVIVAL_LINE + late + upset + ネタ` にした（足し算の順も実測と同じ）。**王者ライン上書き（`final_line`）には足さない**（実測でも上書き時は使われない経路。上書きは呼び出し側が丸ごと決める値なので）。Swift は `CalendarConfig.gpLateBonus(year:)`。中断セーブの復元でも年に応じて付け直す。
- **11年目以降の成長予算 ×0.6^(年−10)**：`late_growth_factor(k)`（k＝累計に足す年）。開始年は決勝の上乗せと同じ 11 を使う（Swift は `lateGrowthStartYear=11` を別に持つが、check_config_sync で Python の `GP_LATE_START_YEAR` と突き合わせる）。Swift の `pow` のため WeekRunner.swift に `import Foundation` を足した（GameCore では JudgeTalk.swift が既に使っている）。
- **大会の経験点**：実測の `install_exp` と同じ位置（perform の直後）・同じ式の順（`pw × K × 重み` → 各通貨に `× 4 × 0.2` を `credit_currency`）。敗退の半分は `× TOURNEY_EXP_LOSS(0.5)`、GP 回戦の基本点は `1 + 0.35 × (通過済みの段)`（シード組は2回戦＝段1から数える＝実測と同じ）。決勝で優勝した週はその場で年が終わるので、決勝の経験点はその年には注がれず次の行動週に注がれる（実測と同じ）。
- **温泉**：`(100, ("mental", 0))`／Swift `bonus: (.メンタル, 0)` にした（エントリを消さず量を0に。実測の差し替えと同じ形）。
- **最初の帯 0.70**：`RANK_COST_BANDS[0]`／`abilityRankCostBands[0]`。

## 段2＝周回（calibration_meta_1102_v0.md §5 推奨 案2＋周回ボーナス型1）

### 実測スクリプトとの一致
- 旧正典＋`exp_calib_meta_1102_v0` の案2（`cb=0.2;cbp=0.3;jt=36;jq=8;ca=2.27;cpw=0.5;cam=14;ex2=300;exq=8`・型1 の ex=4/mo=3）と、新正典＋点だけ渡す（`C.META_POINTS=P`・差し替えなし）を、点8 と点38、帯の組4ボット×ネタ込×n=300・優勝後も15年目まで続ける形で seed ごとに比べた。**点8・点38 とも 1200 seed 全部ビット一致**（やり込みの温泉の穴は段1 と同じく再現して比べた）。

### 細部の決め
- **点の渡し口**：Python は `new_state(meta_points=)`（省略時はモジュールの `META_POINTS`＝0）で `s.meta_points` に持たせ、`run_year` が年初に読む。Swift は `GameState(config:metaPoints:)` で `GameState.metaPoints`（Optional・点0 は nil のまま＝今のセーブと同じ JSON）。年初の上限・予算は `WeekRunner.init` が `state.metaPoints` を読む。**GameConfig ではなく GameState に置いた**理由：点はキャリアごとの値で、中断セーブに一緒に乗る必要がある（config はセーブしない作り＝A-4）。
- **頂点の束の予算 J0**：実測は `bud=J0/P` を経由して `gb=bud·P` を足していた（浮動小数で J0 と最後の桁が違いうる）。正典は J0＝36·(P/38)^8 をそのまま足す。点8・38 の seed 比較では差は出なかった。
- **足し順**：結成時は 型1（経験点・所持金）→ 相性 → 頂点の経験点 の順（実測の差し替えの重なり順と同じ）。年初の予算は `J0 + Σ(...)`（実測の `_gb + sum(...)` と同じ）。
- **所持金**：実測は `3.0×10000×P` で浮動小数になっていた。正典は整数（3万×P・上限100万）。値は同じ。
- 初期経験点の配分（35/27/18/10/10%）は `metaStartExpSplit`（配列）。check_config_sync は配列を読まないので、ここだけ目で合わせた。
- golden（点0）は変わらない。gen_golden の `year_budget(年, P)` も点を受けるようにした（golden は点0 なので通らない分岐）。Swift の単体テスト `CalibrationA1102Tests.testMetaStartAndBudget` で点8・38 の結成時と 1/11/15年目の予算を Python と突き合わせた。
- アプリでトロフィー・図鑑から点を数えて `GameState(config:metaPoints:)` に渡す配線は**していない**（別作業）。
