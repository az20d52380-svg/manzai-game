# 【辛口UIレビュー R4】「ゲームの骨格」が覚醒した。だが、指示を盲目実装したことによる「局所大事故」が2箇所ある

売れているスマホ育成ゲーム（パワプロのサクセス、ウマ娘など）のUIデザイナーとして、今回の改修画面（`g3_week.png`、`g3_allocate.png`、`g3_allocate_after.png`）を容赦なく辛口でレビューします。

率直に言います。**能力アップ画面は化けました。**
「0の海」がハイフン化され、実力のリアルタイム上昇プレビュー（`42 (+1) ➔ 43`）が入った瞬間、死んでいた画面に一気に「商業ゲームの魂」が宿りました。この進歩は素晴らしい。

しかし、**「言われたパーツを無理やり詰め込んだ結果の局所大事故」**が新たに発生しています。
特に能力アップ画面の［−］ボタンは、**UIの禁じ手である「表示領域への操作ボタンの不法侵入（窒息死）」**を引き起こしています。

以下、容赦なく解体し、80点（商業リリース水準）への最終突破口を指示します。

---

## ① 前回の指示が効いた所・効いていない所

### 【週メイン画面（g3_week.png）】
*   **効いた所**:
    *   **「出張中」の二重テキスト解消**: 「今週は撮影」の赤字が完全に消え、斜めテープ1枚で「選べない」ことが直感できるようになり、視覚ノイズが一気に激減した。
    *   **コマンドボタンの解説テキスト全廃**: 「お金を稼ぐ」「体力を戻す」などの所帯じみた案内文が消え、太字のコマンド名（バイト、休む等）が前面に出て、指先でタップしやすい「ゲームのボタン」になった。
    *   **木札と「寄席」看板の重なり解消**: 寄席の看板と木札が物理的に分離され、文字の衝突事故は回避された。
    *   **吹き出しのアンカー自然化**: キャラアイコンの角から自然にしっぽが伸びるようになった。
*   **効いていない所・中途半端な所**:
    *   **「寄席」看板の孤立浮遊**: 被りを避けて左にずらした結果、**何もない壁と畳の境界に四角い落款印がポツンと空中浮遊**している。看板なのか壁掛け時計なのか分からず、舞台美術としての説得力を完全に失っている。
    *   **コマンドアイコンの「Webサービス無料アイコン集」化**: 小判や座布団の判子化を指示したはずが、ピンクのショッピングバッグ（ECサイト風）、緑のドル（¥）、青の三日月（天気アプリ風）など、バラバラな現代Webアイコンが配置され、寄席の世界観を激しく破壊している。

### 【能力アップ画面（g3_allocate.png / after）】
*   **効いた所**:
    *   **「0の海」の全廃（今バージョン最大の勝因）**: 画面を埋め尽くしていた0が消え、ハイフン「-」になったことで、消費する重要数字（8, 6, 23, 42など）だけがベージュのタイルとして目に飛び込んでくるようになった。情報設計として劇的進化。
    *   **実力のリアルタイム変動プレビュー**: `実力 42 (+1) ➔ 43` のエメラルドグリーン表示が入ったことで、「割り振る快感」が生まれた。
    *   **ランクエンブレムの脱・墓石化**: Fが鈍いブロンズ、Dが青銅色、Aが赤金枠になり、育成意欲を削ぐお通夜感が一掃された。
    *   **［−］ボタンの機能実装**: 割り振りすぎたポイントを戻せる安全弁が実装された。
*   **効いていない所・中途半端な所**:
    *   **カード左端の「赤い1px縦線」がまだ残っている**: 前バージョンの残骸である左端の細い赤線が、センス・発想・表現・華・メンタルの全カードにしぶとく残っている。
    *   **「確定」ボタンの金枠が座布団化**: 割り振り時に発光・金枠をつける指示を出したが、枠のoffset/padding計算が狂っており、ボタンの外側にズレた座布団のように膨張して上のグリッドや隣のボタンを侵食している。

## ② 新しく目立った崩れ・AIっぽさ

1. **【最悪の大事故】［−］ボタンの左カラム不法侵入（窒息死レイアウト）**
   - `g3_allocate_after.png` を見て絶句しました。［−］ボタンを実装しろと言われたからといって、**左端の「センス 43」という狭小テキストエリアの中に「44 +1 [-]」を無理やりねじ込んでいます**。
   - 右側にある［＋］ボタンは横幅50pt近くの巨大な正方形なのに、［−］ボタンは極小の暗灰四角で、しかも数値表示の真横にギューギュー詰めに押し込まれている。操作系が左右で完全に分断され、親指の導線も最悪。AIが「要素をどこに置くべきかというUX文脈」を無視し、空いている隙間に力技で押し込んだ典型例です。
2. **【虚空に漂う四角】「寄席」看板の空中浮遊（週メイン）**
   - 背景の何もない虚空に「寄席」という四角いスタンプが浮いています。柱に掛かっているわけでもなく、暖簾でもない。AIに「重なりをなくせ」と命令した結果、座標だけを雑に左へずらして放置した痕跡です。
3. **【世界観崩壊のWebアイコン】（週メイン）**
   - 「お店」のアイコンが、AmazonやBASEのような「ピンクの買い物袋（ハンドル付き紙袋）」。大正・昭和の演芸場・寄席の世界観に、原宿のセレクトショップのショッパーが混ざっています。「バイト」も緑地に白抜きの「¥」で、フィンテックアプリのUIパーツが紛れ込んだような違和感があります。
4. **【確定ボタンの枠線膨張事故】（能力アップ）**
   - ＋を押した後の「確定」ボタンの金枠が、ボタンの当たり判定や背景矩形から大きく外側にはみ出し、上の「メンタル」行の底辺に衝突しています。

## ③ 次に直す指示を画面ごと優先順に5個（SwiftUI実装レベル）

---

### ■ 週メイン画面（`g3_week.png`）改善指示 TOP5

#### 1. 【舞台美術の再構築】「寄席」看板の虚空浮遊を解消し、壁面オブジェとして定着
*   **問題**: 背景の中央〜右の空間に「寄席」の四角がポツンと浮いていてシュール。
*   **実装指示**:
    *   背景に薄い木目調の「長押（なげし：水平の横木）」を1本通す（`Rectangle().fill(Color(hex: "8D6E63")).frame(height: 8)`）。
    *   「寄席」看板は、その横木から紐で吊るされている木彫り看板、あるいは寄席の壁に貼られた千社札風（縦長の長方形 `width: 28pt, height: 64pt`、黒枠＋白地＋勘亭流文字）に変更して壁面に固定する。
    *   これで背景の空間に「演芸場の楽屋・舞台裏」としての奥行きと説得力が生まれる。

#### 2. 【世界観の統一】コマンドアイコンの和風トーン統一（脱・無料Webアイコン）
*   **問題**: ピンクの紙袋、緑の¥など、現代Webサービスのアイコンが混入して世界観が台無し。
*   **実装指示**:
    *   ボタン左側のアイコンを「和の単色トーン（墨黒 `#2C2C2C` または 朱赤 `#A62B1E`）」に統一:
        *   **バイト**: 小判型アイコン、または「銭」の角印（背景角丸のベタ塗りは廃止）。
        *   **休む**: 布団／座布団のピクトグラム。
        *   **能力アップ**: 開いた「扇子」のピクトグラム。
        *   **お店**: 暖簾（のれん）または風呂敷包みのピクトグラム（紙袋は即刻廃止）。
    *   これで画面全体のトーンが「寄席の粋な世界観」に引き締まる。

#### 3. 【主役感の復権】漫才師キャラクターとサンパチマイクの拡大（15%スケールアップ）
*   **問題**: 中央の漫才師の後ろ姿が小さく、上部に広大な無駄スペース（虚無の空間）が生じている。
*   **実装指示**:
    *   漫才師2人とサンパチマイクのView全体を `scaleEffect(1.15)` 程度拡大し、画面中央下部にどっしり構えさせる。
    *   プレイヤーの分身であるコンビの後ろ姿を画面の主役に据え、ステージの臨場感を出す。

#### 4. 【視認性改善】提灯ゲージの「点灯／消灯」コントラスト強化
*   **問題**: 満タンの提灯（緑）が暗すぎて、一見すると消灯している（空っぽの）ように見える。
*   **実装指示**:
    *   **満タン・点灯時**: 明るく鮮やかな若竹色〜萌黄色（`Color(hex: "4CAF50")`）にし、中央にふんわり白のインナーグロー（`radialGradient`）を入れて「和紙の中で蝋燭が灯っている」発光感を出す。
    *   **消費・消灯時**: 完全に煤けた暗いチャコールグレー（`Color(hex: "333333").opacity(0.5)`）。
    *   点灯と消灯の明度差をハッキリつけ、現在の体力を一目で把握させる。

#### 5. 【木札の質感整理】右上ステータス木札のグラフィック統合
*   **問題**: 木札のテクスチャがビットマップ風で荒く、相性の赤いバーがただの四角い板に見える。
*   **実装指示**:
    *   木札全体をSwiftUIのベクター描画で統一:
        *   背景: `RoundedRectangle(cornerRadius: 6).fill(Color(hex: "E0C9A6"))` ＋ 薄いウッドシャドウ。
        *   画鋲ピンのイラストは削除（余計なノイズ）。
        *   「相性」下の赤いバーを、ちゃんとした進行度ゲージ（下地: 薄い木肌色、バー: 鮮やかな朱赤 `#C0392B`、角丸 `3pt`）として再定義。

### ■ 能力アップ画面（`g3_allocate.png / after`）改善指示 TOP5

#### 1. 【最優先・大事故修正】［−］ボタンの救出と「操作ボタン列」の正規化
*   **問題**: ［−］ボタンが左端の数値表示エリアにめり込み、文字とボタンが押し合って窒息している。
*   **実装指示**:
    *   左カラム（幅 `64pt`）には**ステータス名と数値のみ**を配置（余計なボタンは絶対に入れない）。
        *   通常時: `センス \n 43`
        *   加算時: `センス \n 43` ＋ 右横に小さく緑太字で `+1`（`font(.caption.bold())`）
    *   **操作ボタンは［＋］のエリアに統合**:
        *   各行のボタンエリア（幅 `60pt`）を用意。
        *   ポイント未割り振り時（加算0）: ［＋］ボタン（幅 `48pt`）を中央配置。
        *   ポイント割り振り時（加算1以上）: HStackで **［−］（幅 `24pt`, 背景灰 `#606060`）と［＋］（幅 `24pt`, 背景赤 `#B83A2A`）を綺麗に横並び**で配置。
    *   これで「数値表示」と「増減操作」の責務が完全に分離され、指先でも迷わず増減できるようになる。

#### 2. 【大事故修正】「確定」ボタンの金枠ズレ（座布団化）の解消
*   **問題**: ＋を押した後の確定ボタンの金枠が外側にはみ出し、上の行や隣のボタンに被っている。
*   **実装指示**:
    *   ボタンの外側に余白を取って枠をつけるのをやめ、ボタン自体の内部に枠線を描画する:
        ```swift
        Button(...) { ... }
        .frame(height: 48)
        .background(
            LinearGradient(colors: [Color(hex: "C0392B"), Color(hex: "8A1F13")], startPoint: .top, endPoint: .bottom)
        )
        .cornerRadius(6)
        .overlay(
            RoundedRectangle(cornerRadius: 6)
                .strokeBorder(isChanged ? Color(hex: "FFD700") : Color.clear, lineWidth: 2)
        )
        .shadow(color: isChanged ? Color(hex: "FFD700").opacity(0.4) : .clear, radius: 4)
        ```
    *   `.overlay` と `.strokeBorder` を使えば、外側のレイアウトを1ミリも破壊せずに内側にビシッと美しい金枠が収まる。

#### 3. 【ゴミ掃除】ステータスカード左端の「赤い1px縦線」完全撲滅
*   **問題**: センス・発想・表現・華・メンタルのカード左端に、前バージョンの遺品である赤い縦線が残っている。
*   **実装指示**:
    *   上部カード（StatusCardView）の最左端にある `Rectangle().fill(Color.red).frame(width: 2)` 等のビューコードを**完全に削除**。
    *   六角形エンブレムとゲージだけの綺麗な白地カードに仕上げる。

#### 4. 【リズムの統一】「-」（ハイフン）セルの薄枠プレート化
*   **問題**: 数字のあるセルだけベージュの角丸タイルがあり、「-」のセルは背景がないため、画面全体のグリッドが歯抜けに見える。
*   **実装指示**:
    *   5×5のすべてのマスに、あらかじめ薄いベースプレート（`RoundedRectangle(cornerRadius: 4).fill(Color.black.opacity(0.03))`）を敷く。
    *   その上で:
        *   **消費なし（-）**: プレートの上に薄いグレー文字（`#A0A0A0`）で「-」を表示。
        *   **消費あり（数字）**: プレートを明るいベージュ（`Color(hex: "F5EFE6")`）に切り替え、太字の黒文字で数値を表示。
    *   これでグリッドの垂直・水平のリズムがピシッと揃い、Excel感が消えて高級ボードゲームの盤面のようになる。

#### 5. 【視線誘導の極み】経験点ヘッダーの消費予定ポイントの減算プレビュー
*   **問題**: ＋を押した際、現在の経験点が減っているが、どこがいくら減ったのか直感的に追えない。
*   **実装指示**:
    *   上部の「現在の経験点」の丸アイコン（閃・語・間・存・胆）の下の数値において、ポイントを仮割り振りした際、減算アニメーションを入れる。
    *   例: 閃 `120` ➔ `98` の下に、小さく赤文字で `(-22)` を添える。
    *   「これを上げると閃きが22減るんだな」と指先と目が完全に連動し、育成シミュレーションとしての納得感が跳ね上がる。

### デザイナーからの総括

前回のレビューで指摘した構造改革（Grid整列、0のハイフン化、プレビュー表示）が見事に機能し、**能力アップ画面は76点まで到達しました。市販ゲームの背中が完全に捉えられています。**

だからこそ、**「［−］ボタンを左端の数字ラベルに無理やり押し込む」という雑な実装**が猛烈にもったいない！

週メイン画面も、文字の渋滞が消えて劇的に見やすくなりました。あとは「浮遊する寄席看板」を壁に定着させ、「ピンクの買い物袋」のような世界観クラッシャーを駆逐して和風の粋なグラフィックに統一してください。あと一歩です！
