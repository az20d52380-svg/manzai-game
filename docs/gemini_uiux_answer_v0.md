ゲームUIデザイナーとして、ご提示いただいた課題を解決するためのデザイン戦略を提案します。

「AIっぽさ」の正体は、**「情報の重要度に差がなく、OS標準の便利ツールのように見えること」**です。これを、手触りと伝統の重みを感じる「エンターテインメントのUI」へ昇華させます。

---

### 1. AI っぽさの原因（10個の指摘）

1.  **「等価な角丸カード」の羅列**: すべての要素が同じ半径の白い箱に入っており、何が重要で何が背景かが判別しにくい。
2.  **SF Symbols の素通し**: iOS標準アイコンをそのまま使うと、システム設定画面のような「事務的」な印象を与えます。
3.  **無機質なプログレスバー**: 直線の細いゲージは「ダウンロード中」に見えます。ゲームの「熱量」が伝わりません。
4.  **余白の均一性**: 上下左右に正確すぎる余白があるため、ライブ感や「寄席の密集感」が消えています。
5.  **フローティング（浮いた）要素**: 画面から浮き上がった影付きカードは、Webアプリ的なモダンさを出しすぎて「和」の重厚さと矛盾します。
6.  **中央揃えの多用**: 情報を中央に置くだけでは、ダイナミックな視線誘導が生まれず、静止した「説明文」に見えます。
7.  **「＋」ボタンの汎用性**: 青い丸に白抜きの＋は、OSの連絡先追加ボタンと同じで「育成のワクワク」がありません。
8.  **パステル調のアクセント**: 試作前の青や紫のグラデーションは「ハイテク・近未来」を想起させ、漫才の泥臭さと乖離しています。
9.  **情報の「密度」の低さ**: 1画面あたりの情報が整理されすぎており、ハイスコアを目指すゲーム特有の「攻略している感覚」が薄いです。
10. **フォントの使い分け不足**: 数字、見出し、本文がすべて同じウェイト（太さ）に見え、数字が「跳ねて」見えません。

### 2. デザインシステム（漫才道・デザイン帖）

#### ■ 色（Color Scheme）
*   **地（背景）**: `生成り (#F5F0E1)` - 紙や木札の温かみ。
*   **面（枠・帯）**: `墨 (#2B2B2B)` - 情報を引き締める。
*   **文字（基本）**: `墨 (#2B2B2B)` / **反転文字**: `生成り (#F5F0E1)`
*   **強調（朱）**: `朱 (#BD3C28)` - 重要なボタン、現在の週。
*   **深い強調（臙脂）**: `臙脂 (#7D221E)` - ヘッダー、ステージの幕。
*   **豪華（金）**: `消金色 (#C1A550)` - 優勝、Sランク、確定ボタン。
*   **成功（緑）**: `常磐色 (#2E583C)` - 体力回復、能力上昇。
*   **押せない（灰）**: `銀鼠 (#9E9E9E)` - 経験点不足の状態。

#### ■ 文字（Typography）
*   **見出し（特大）**: 32pt / Bold / **縁取り（金・白）**
    *   寄席文字風に字間を詰め、少し縦長に配置。
*   **数字（スコア）**: 28pt / **Din Condensed系（iOS標準の太い数字）**
    *   「数値」はゲームの命。本文より一回り大きく、少し「朱」を混ぜる。
*   **本文**: 16pt / Medium - 読みやすさ重視。
*   **注記**: 12pt / Regular - 補足情報。

#### ■ 形（Shapes）
*   **脱・角丸カード**:
    *   「木札（長方形・角なし）」
    *   「貼り紙（角の1箇所だけ折れている、または少しだけ歪んでいる）」
    *   「幕（上部だけが波打っている形状）」
*   **線**: 1.5pt〜2pt。細い線はやめ、筆圧を感じるような「入り抜き」のある線を意識。
*   **影**: 下方向への強い影（黒 40% / Blur 0）を使い、「浮いている」のではなく「置いてある」重さを出す。

#### ■ 動き（Motion）
*   **ボタン**: 押した瞬間に `-2pt` 下に沈み込む（物理的なスイッチ感）。
*   **数字**: 経験点が入る際は「ポポポポッ」とカウントアップ。
*   **結果**: 判子は「ドンッ」と画面が揺れる振動（Haptics）と共に表示。

### 3. 画面ごとの設計図 (393×852pt)

#### ① 週のメイン画面
*   **0-80**: 【ヘッダー】臙脂色の帯。「1年目 第12週」を金文字で。
*   **80-350**: 【メインビジュアル】劇場の舞台。センターマイクとコンビの背中。
    *   右側に「木札」形式で現在の実力・相性を表示。
*   **350-650**: 【コマンド】2列×3段の「貼り紙」ボタン。
    *   各ボタンは墨の太い縁取り。選択中のコマンドは「朱」で発光。
*   **650-750**: 【ステータス】体力を「湯呑みの茶」や「提灯の火」の並びで表現。
*   **750-852**: 【フッター】タブバー。アイコンではなく「日程」「コンビ」「設定」の漢字2文字。

#### ② 能力アップ画面（パワプロ風）
*   **100-250**: 【ランク表示】5つの能力（センス〜メンタル）を横に並べる。
    *   各能力の下に「次のランクまで」の細いゲージ。
*   **250-320**: 【所持経験点】5種類の経験点を横一列に。アイコンではなく「閃」「語」などの漢字1文字を丸囲みで。
*   **320-720**: 【能力アップ表】
    | 能力 | ＋ | 閃 | 語 | 間 | 存 | 胆 |
    | :--- | :---: | :---: | :---: | :---: | :---: | :---: |
    | センス | [＋] | 10 | 0 | 5 | 0 | 0 |
    | 発想 | [＋] | 10 | 5 | 0 | 0 | 0 |
    *   **手応えの工夫**: 経験点が足りる行の[＋]は「朱」。足りない行は「灰」。
    *   [＋]を押した瞬間、その行が「白」から「金」に一瞬光り、所持経験点から数字がマイナスされ、能力値が「＋1」と跳ねる。
*   **720-852**: 【フッターボタン】
    *   「戻る」「リセット」「おまかせ」「確定」を、同じ幅で4つ並べる。
    *   「確定」のみ臙脂色（または金）で太く。

#### ③ ネタ帳
*   **上部**: 「持ちネタ 3/10」の筆文字。
*   **中央**: 「短冊」を縦に並べたようなリスト。
    *   ネタ名が太字。完成度を「筆で書いたような太い線」で表示。
    *   「勝負ネタ」には「真剣勝負」という赤い判子。

#### ④ 大会結果
*   **上部**: 大会名「M-1予選」などの看板。
*   **中央**: 「笑いの波形」を筆のカスレのようなエフェクトで。
*   **下部**: 審査員7人の顔アイコン（丸）と、その下に「85」「92」などの数字。
    *   一気に全員分出さず、左から順に「ド、ド、ド、ドン！」と出す。

### 4. SwiftUI で作るための指示

#### カラー定義
```swift
extension Color {
    static let yoseKinari = Color(hex: "F5F0E1")
    static let yoseSumi = Color(hex: "2B2B2B")
    static let yoseShu = Color(hex: "BD3C28")
    static let yoseKin = Color(hex: "C1A550")
}
```

#### YoseMoji モディファイア（縁取りと影）
```swift
struct YoseTitle: ViewModifier {
    func body(content: Content) -> some View {
        content
            .font(.system(size: 24, weight: .heavy, design: .default))
            .foregroundColor(.yoseKinari)
            .shadow(color: .yoseSumi, radius: 0, x: 2, y: 2) // 強い影
            .padding(.horizontal, 8)
            .background(Color.yoseShu)
    }
}
```

#### 部品構成の考え方
*   **GridStack**: 能力アップ画面は `Grid` を使用し、列の幅を固定してパワプロ的な整列を維持する。
*   **AnimatableModifier**: カウントアップする数字にはこれを使い、数値が増える際の「跳ね」を実装する。
*   **Buttonスタイル**: `ButtonStyle` を自作し、`configuration.isPressed` の時に `offset(y: 2)` となるようにして物理的な手応えを作る。
