# お金の書式の棚卸しと統一案（判断の材料） v0 / 2026-10-27

## まとめ（3行）
- お金の書き方は実装上 **7種類**（¥万・¥,区切り・円・万円・万だけ・「+◯万」・漢数字の台詞）。札の中だけでも ¥万（Yen.man）・「1万未満だけ ¥5,000」（costPill）・帯の ¥300,000 が混ざる。
- 混ざる主因は2つ：(a) `Yen.man` は 1万未満でも「0.5万」を返す（5,000→"0.5万"）ため、呼び出し側が個別に避けている（WeekMainView:1347）。(b) 札・帯・文章の役割分担が決まっていない。
- 推奨は **C（役割で決める）**。変更は札の外のごく少数（約12行）で済み、既存の「1万未満は円」という配慮も活きる。決めるのはオーナー。

## 2. 統一案
### A　札はすべて「¥◯万」（1万未満も ¥0.5万）
- 変わる所：costPill（1347行の分岐を消す＝約2行）。ほか札は変更なし。
- 良い点：札は常に同じ形で、1行で意味が揃う。実装が一番単純。
- 気になる点：「-¥0.5万」「-¥0.3万」は読みにくく、5,000円や3,000円という実感の金額が1回見えなくなる（10/26 に「¥0.5万を出さない」としたのは、これを避けるためだった）。

### B　札は1万未満だけ「¥5,000」（今のまま）
- 変わる所：なし（現状維持）。
- 良い点：金額の実感が残る。手を入れない。
- 気になる点：-¥5,000 と -¥1万 が並ぶ札・並ぶ瞬間が残り、「混ざって見える」問題は解消しない。帯の ¥300,000 や文中の「14万円」との差も残る。

### C　役割で決める（札＝¥、文＝円。1万未満は円で出すのは全場所で共通）
- 札・帯・ピル・ボタン（数字だけ見る所）：**¥◯万 ／ 1万未満は ¥5,000**。帯（YoseGameParts:66）の ¥300,000 は ¥30万 にそろえる（3桁区切りの長い数字は7桁で折れた前例もある）。
- 文の中（説明・ヒント・選択肢・用語）：**◯万円 ／ ◯,◯◯◯円**（「¥」を文に混ぜない）。
- ログ・帳面・賞金ラインのような「単位表のある数字」：「万」だけ（今のまま）。
- 変わる行（目安）：ShopView 4行・StageViews:211-222 の4行＝「¥」→「円」（文中なので）／YoseGameParts:66 と CalendarView:47・優勝演出＝区切り→万（3〜4行）／オファー札 881行＝ ¥ を付けるか（1行）／1135 の札は 1万未満の分岐を 1347 と共通化（Yen に1関数足す、呼び出し2行）。計およそ12〜15行、画面は約8つ。
- 良い点：「札＝¥、文＝円」という ui_wording_check #1 の使い分けにそのまま沿う。札の1万未満の配慮も全体に広がる。
- 気になる点：帯の ¥300,000 が ¥30万 になると、1,000円単位の細かい増減（−¥5,000 など）が帯上で見えにくくなる（帯だけ区切り表記を残す手もある＝C'）。

## 3. 推奨
**C**。理由：①オーナーが札でだけ「混ざって見える」と感じているので、札と帯のそろえと、文中の円を同じ基準にするのが一番素直。②「Yen.man が 1万未満で 0.5万を返す」穴を、`Yen.man` ではなく共通の関数（例：`Yen.short(v)`＝1万未満は ¥5,000、以上は ¥◯万）に集めると、1135・1347・カーテンの3か所が同じ出力になり、以後は増えない。③文章側は「円」に統一なので、ui_wording_check #1 の中程度の指摘がそのまま片付く。
帯だけは ¥300,000 のまま残すか ¥30万 にするか、オーナーに見てもらうのがよい（残す場合は C'）。
