## §1 規則の要約（grammar §9 をこのゲームに当てはめた形）

1. **具体物を必ず1つ。** 「良かった」「素晴らしい」だけの講評はゼロ。具体物は「出だしの〜」「中盤の〜」「〜なツッコミ」「最後の〜」のような**場所と形**か、ネタの名前『◯◯』。ボケの中身は書かない（場所と形だけを指す）。
2. **決勝の口頭は1〜3文。** 順番は「結論（点の理由か体感）→具体物→条件付きの惜しさ」。惜しさは「〜を半分に」「〜の前に一拍」のように直せる形で1つだけ。
3. **第一声で「いやー」等の感嘆を使わない。** 評価の一言（「〜の一拍。」）、状況（「トップバッターって〜」）、体感（「途中からペンを置いて〜」）から入る。
4. **観点は1つ（多くても2つ）。** 全部を褒める羅列はしない。
5. **人ごとに声を固定**（§3）。
6. 決勝で「来年」など結果を先に言う言葉を使わない。点数や能力の数字を言わない。「笑」の字を使わない（従来の決まり）。
7. **紙の講評は事務的な2点**：「良かった点。直す点。」の体言止め寄り【仮】。
8. ネタ名を入れる行は全体の4分の1ほど（毎回ではない）。名前が無い時（ネタ未選択）は名前の行を候補から外す。

## §6 仕組み（作業者向け）

- 本体: `GameCore/Sources/GameCore/JudgeTalk.swift`。`Scene`（ネタ名・型・鉄板/再演/おろしたて・ハマった夜・点差・出順・敗者復活・相性/体力/メンタル/華）を作り、`finalComment` / `paperReview` が文を選んで差し込む。
- 選び方: `mix(salt, k)`＝整数を混ぜて割るだけ。乱数（RandomSource）は呼ばない＝golden 不変。salt は従来どおり（予選＝年×131＋週、決勝＝点＋年×7＋出順＋何人目）。
- 窓口: 予選 `JudgeData.review(passed:state:salt:config:year:margin:burst:)`（その本番のネタは `state.selectedNetaID`）、決勝 `FinalsJudgeTalk.comment(judge:score:high:scene:salt:)`（`FinalsPresentationView.judgeScene`）。司会の拾いは返り値の `pickup`（言い直しにも具体物が入る）。DEBUG の `MZ_PICKUP` も従来どおり使える。
- GameCore に置いた理由: 差し込みを `swift test` で確かめるため（アプリ側にテストの入れ物が無い）。式・乱数には触れていない。
- テスト: `GameCore/Tests/GameCoreTests/JudgeTalkTests.swift`（7本）＝全審査員×全帯×最高/最低×全型＋型なし×名前あり/なし×状態の組み合わせで「具体物が入る」「差し込み口が残らない」「笑・来年が無い」「最低点専用の行が最高点に出ない」、名前なしで『』が出ない、決定的、同じ条件で12通り以上に散る。
