# オファーが体力不足の週に来る頻度（判断待ち167の材料・記録のみ）

2026-11-08 定期の回。式・golden・アプリは触っていない（実測だけ）。

## 何を測ったか
- 判断待ち167：体力が足りない週でもオファーの札は押せて、体力は0で止まる（稽古の札だけ staminaGate=20 の門がある）。
- 「体力不足」＝その時の体力＋オファーの体力（−10〜−25）が0未満（＝押すと体力0で止まる）。
- 実測機 sim_career（ネタ込み NETA_ON/V2）・ボット2種・n=300・15年。1枚目のオファー（B.roll_offer）だけを数えた（追加の札 extra_offers は別の決定論なので数えていない）。

## 結果（1キャリアあたり）
| EVENTS_APP | ボット | 来た | 体力不足で来た | 受けた | 受けた内の体力不足 | 受けて体力0 |
|---|---|---|---|---|---|---|
| False | Balanced | 226 | 22% | 225 | 22% | 27% |
| False | Smart | 222 | 14% | 185 | 14% | 17% |
| True | Balanced | 240 | 23% | 239 | 23% | 27% |
| True | Smart | 240 | 15% | 200 | 14% | 17% |

- ボットはほぼ全部受ける＝1キャリアで **約30〜50回、体力0で週を終える**（受けて体力0 は「ちょうど0」も含む）。
- 人の遊び方では受ける率は下がるはず（ボットは体力の門を見ない）。数は上限の目安。

## 体力0で何が起きるか（今の仕様）
- 次の週：稽古の札が門で押せない（谷口が止める）。
- キツいバイト：体力50未満なら体調ダウンの抽選（INJURY_TH=50）。
- 大会の週に体力が低いまま：staminaPenalties（10未満 −15・30未満 −10・50未満 −5）。
- 札には二度押しの確認がある（WeekMainView.swift:910）が、「体力0になる」とは書いていない。

## 選択肢への影響（決めるのはオーナー）
- ①今のまま：数字上は毎キャリア数十回起きる。罰は「次週稽古できない」程度で、自然に休みへ誘導される。
- ②札に小さく「体力0になる」：表示だけ・式・golden 不変・実測の基準も不変。
- ③オファーにも門：ボットの行動が変わる＝実測の基準（帯）が動く。入れるなら Python 側で既定無効のフラグから（規律A）。
- 推奨は既存どおり②（表示だけで情報の食い違いが消え、基準を動かさない）。
