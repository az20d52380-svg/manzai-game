# 知名度「その他の伸び」×0.6 と ×1.0 で決勝到達が逆転する理由（診断）v0（2026-10-19）

全て【仮】。決めない（決めるのはオーナー）。スクリプト `tools/diag_fame_mult_v0.py`・生出力 `docs/measure_raw/diag_fame_mult_v0.json`。式・既定値は不変（子プロセス内の上書きのみ）。

## 要点3行
- 原因：知名度が早く上がるとオファー率の帯（10/30/55）を早く越え、**オファーを1キャリアで約+20〜25回多く受け**、テレビ慣れ（直近6週に4回以上→受けるたび感度・表現−0.5）の発動が **+3回前後** 増える。GP準決勝（ライン72）では実力が −1・相性が −0.5 ほど足りず、通過が 15%→10%（やり込み・APP=True）。テレビ慣れを切ると差は −13→−6pt（APP=False）・−13→−2pt（APP=True）に縮み、オファーを無しにすると逆転が消える。
- 知名度帯のイベント（<20 等）や決勝の人気補正（FAME_FINAL_BONUS）は主因ではない（人気補正を0にしても決勝到達は不変。イベントは総数が同じで内訳が少し動くだけ）。体力ペナルティも主因ではない。
- 意図どおりか：「売れるほど忙しくなり芸が荒れる」というテレビ慣れの設計意図には沿うが、「知名度が上がりやすいほど決勝に遠のく」は意図とは言えない副作用（ボットが来たオファーを全部受けるため）。人間の遊び方で同じかは未測定。

節構成：§1 比べ方／§2 差の表／§3 原因（仮説ごとの潰し）／§4 意図どおりか・直すなら案（決めない）

## §3 原因（仮説ごと）
- **①テレビ慣れ：主因。** 知名度が上がるほどオファー率は 5%→15%→30%→50%/週と上がり、ボットは来たオファーを受けるので受ける数が約+20〜25。慣れの発動が+3回/キャリア増え、そのたび感度・表現−0.5。準決勝は「実力＋相性」が62付近でライン72に届くかの勝負＝わずか −1 で通過が15%→10%。慣れを切ると差は 66/54 → 73/67（APP=False）・76/63 → 83/81（APP=True）に縮む。残りはブレ＋下記③。
- ②知名度帯のイベント：**主因ではない（効きは小さい）。** 総発火数は同じ（22.8 対 22.8／39.7 対 39.3）。<20 帯のもの（lineuptop・lasttrain・renovation 等）が約−0.15回/キャリア、知名度が高いほど出るもの（fan・photo・kouhai）が約+0.15回。単独の切り分けまではしていない。
- ③オファーを受ける週が増え稽古が減る：**稽古は減らない**（上表）。増えたオファーはバイト週を置き換える。ただし変な仕事への置換（知名度<20・乱数で1回あたり小銭＋能力+1・慣れ無し）が減る分、慣れのある本物のオファーが増える。noweird（置換を無くす）は **×0.6・×1.0 とも決勝到達を大きく下げる**（やり込み 66→46、54→32）＝知名度が低い間の置換は安全弁として効いている。
- ④決勝の人気補正：**無関係。** nofinal は決勝到達が現状と同じ（人気補正は決勝にだけ効く＝到達後の優勝%にだけ出る）。
- 体力ペナルティ（nostam）：差を縮めない（66/56、79/67）。
- 逆の確認：nooff（オファー無し）では ×1.0 が ×0.6 と同等以上（やり込み 71 対 67・76 対 76）＝知名度が早く上がること自体は害でなく、オファー経由の慣れが害。

## §4 これは意図どおりか・直すなら案（決めない）
- 意図：テレビ慣れは「出すぎて腕が落ちる」ブレーキとして入れたもの（オファーを受け続けるのに歯止め）。知名度が上がるほどオファーが増えるのも設計どおり。**ただし係数を上げると到達が下がる向きは、キュー62 の『知名度が高い＝大御所／決勝で有利』という狙いとは逆**で、正典に書かれた意図とは言い切れない。ボットは来たオファーを全部受ける（慣れ発動中でも受ける）ので、人間が慣れを見て断る遊び方では差が小さいかもしれない（未測定）。
- 案（どれも決めない。数字は本書の変種から推定で、実装後に測り直しが要る）：
  1. このまま（現状 ×0.6 は差が小さい側。ボットの挙動の問題として扱う）。
  2. ボットの方針に「慣れ発動中のオファーは断る」を足して測り直す（式は触らない。人間の遊び方に近づける）。
  3. 慣れの閾値を緩める（4回→5回／窓6週→5週）。nofat 相当で差は −6／−2pt まで縮む。
  4. 高知名度帯のオファー率を下げる（0.50→0.35 等）。×0.6 と ×1.0 の差を縮める方向。
  5. 提案どおり ×0.6 を採る理由を「慣れの副作用が小さい側」と文書に明記する（実装変更なし）。
