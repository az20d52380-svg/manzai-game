**このブランチ（`ability-exchange-proposal`）だけの試作。本体ブランチ・preview-all には入れていない。**
出発点: `docs/ability_stall_measure_v0.md`（今の配合だと1〜3年目の79〜93%の週で「経験点はあるのに押せる＋が0」。間合いが余り、語彙・閃き・胆力が足りない。おまかせでも詰まる）。

## 1. 決まり（入れたもの）
- **交換はおまかせ（recommendedPlan）の中だけ・どの能力も押せない時に限る。** 乱数は使わない。
- 交換の相手: 伸び余地がある（1段の見える伸び>0.05）能力のうち、**今の値が一番低いもの**（同じなら センス→発想→表現→華→メンタル の順）。
- 払う粒: その能力の**配合に無い粒**だけ。残高の多い順（同じなら 閃き→語彙→間合い→存在感→胆力 の順）。
- 率: **余り2つ → 足りない粒1つ**。1段（allocationStep）押すのにちょうど足りない分だけ受け取り、すぐ1段押す。余りが足りなければ交換しない。
- 押せる能力が1つでもある間は今までと全く同じ（交換しない）。人の手配り（＋ボタン）は押せる能力しか押せないので、交換は起きない。
- 供給: `EXP_SUPPLY_SCALE` / `expSupplyScale` を **0.48 → 0.24（×0.5）** に再較正。
- 値の置き場: `tools/balance_sim.py`（EXCHANGE_ON / EXCHANGE_RATE=2.0 / EXCHANGE_MIN_GAIN=0.05・`exchange` / `pour_tap` / `recommended_plan`）、`GameConfig`（exchangeEnabled / exchangeRate / exchangeMinGain / expSupplyScale）、`GameEngine`（Allocation.swift の `exchange` / `pourTap` / `recommendedPlan`）。WeekRunner.applyAllocation とアプリのプレビューは `pourTap` で再生。

## 3. 気になる点（判断の材料）
1. **やり込みの解散が12.9%→0.7%に減る**（どの倍率でも）。のびが揃うと相性を削る選び方をしなくなる＝ボットの選択の副作用。エンディング#2（解散）の出方が変わる。
2. **ゆるいボットの順位が入れ替わる**: のんびり改 3→14%（上がる）、ローテ 18→8%（下がる）。今まで「間合いを使わない能力（発想・華）だけ伸ばす」ローテが得をしていた分が消え、5能力が揃って伸びる。
3. 3年末の実力値は、普通のボットで2前後下がる（20→18）。交換で捨てていた粒が使えるようになる分を、供給×0.5が少し上回る。1年目末は12.7〜12.9（今13.3〜13.5）。
4. 調整型（賢い）は逆に上がる（14.9→16.6）＝余り（存在感）を使えるようになるため。
5. 一言の数字（例「余った間合い19を、閃き3と存在感6に替えた」）は経験点の表示（内部×10の切り捨て）なので、19:9 のように2:1ぴったりに見えないことがある。
