## §2 照合
1. **ボイトレ（CommandData ↔ GameConfig.trainings[.ボイトレ]）**：cost 80,000（ネタ見せ会・エントリーライブと同額）。説明は「安い部屋を借りて」＝安さを言う。他の8万円コマンドの説明は「作家の前で」「出演料を払って」「お題に答えて」と費用が高い理由が読める。
2. **サウナ ↔ roomHeals／roomBestMental**：家で休む（完全休養・気分転換）は部屋の段で +10／+20 の体力加算。いい部屋では家＝80（メンタル+3）、サウナ＝80（メンタル+2・1万円）。「家よりよく休める」は部屋が安い・ふつうの時だけ正しい。
3. **提供割合の注記 ↔ GachaState.pullOne**：`totalPulls == 0` で drawFirst（特別確定）。割合は「回数で変わらない」が偽になる。
4. **体調ダウンの知らせ ↔ WeekRunner.resolveAction**：risky＝稽古（.train）かキツいバイト、体力<injuryThreshold(50)で確率抽選、療養 injuryRestWeeks(3)・メンタル-5。文は一致。
5. **オファー説明 ↔ offersNamed**：4種とも収入・知名度・体力・能力と矛盾なし。続けて受けた時の腕の低下（offerFatigue*）は説明に出さず谷口の一言が担当。
6. **ガチャの数字 ↔ GachaState／GachaCatalog**：すべて定数から生成されるので表示と実際は一致（手書きの数字なし）。

## §3 直し案
A 直した（候補 claude/session-command-text-fix-cand・2a91f0c9・アプリ402テスト失敗0）：× の1件。GachaRatesView の注記を「前の結果や回数で変わりません（初回の1回と、天井の交換を除く）。」に。文字列のみ・ロジック／確率／GameConfig／セーブの鍵は不変。GameCore は触っていない（check_golden_sync 一致・config sync 80/80）。
B △の案（直していない）：
- ボイトレ：「声出し」の名前を「貸しスタジオで声出し／防音の部屋を借りて声を通す練習」に（8万円が自然）。または費用側（判断）。
- サウナ：説明を「しっかり休める（有料）」に（部屋に依らず真）。
- 相方と合わせる：説明を「二人で通してみる」等に（重なり解消・ただし「通す」は業界語気味なので「二人で何度もやってみる」）。
- ネタ名：引っ越し系の2つを別の題材に。
- 提供割合：天井の項は「ポイント」に揃える（gacha_text_score B と同じ）。

## §4 判断が要る論点
1. ネタの型の表示名（つかみ型・畳みかけ・飛び道具・リターン型）を、画面に出る日が来る前に言い換えるか。いまは未使用だがテストが固定している（ManzaiGameTests:1005 ほか）。
2. ボイトレの「安い部屋」：文を直すか、費用（8万円）を見直すか。費用は GameConfig＝較正の領域で、私は触っていない。
3. 【仮】を公開時に外す運用でよいか（gacha_text_score §4-2 と同一）。
4. 優勝の夜の「日本一」を THE HANA 優勝でも使うか（scene_ending_fx §4 と同一）。
