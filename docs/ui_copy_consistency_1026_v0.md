## §1 閉じる／戻る／やめる（重要度：中）
| 形 | 場所 | 用途 |
|---|---|---|
| 閉じる | ChoiceEventOverlay:281、QualifierNoticeView:143（通過しなかった時） | 画面を閉じる |
| とじる | YoseComponents:10（closeTitle 既定）、WeekMainView:725（ネタ棚）、EndingViews:91、NetaSelectionView:62「とじる ▲」 | 画面／棚を閉じる |
| 戻る | AbilityUpView:420（反映せず閉じる）、ShopView:109（引っ越しの「戻る」＝元の部屋に戻す） | 閉じる／元に戻す、2つの意味が混在 |
| もどる | WeekMainView:636（Label＋chevron） | 前の画面へ |
| 画面をタップして閉じる ▶ | YoseRankUpOverlay:99 | 閉じる |
| やめる | AbilityUpView:109（特技を覚えるのをやめる・cancel） | 取り消し |

- ゆれ：「閉じる」(2)／「とじる」(4)／「戻る」(2)／「もどる」(1) が同じ「画面を閉じる・出る」で混在。漢字・ひらがなが画面ごとに違う。
- 意図的な可能性：ShopView の「戻る」は「元の部屋に戻す」の意味で別物。AbilityUpView:420 は「反映せず閉じる」なのでキャンセル寄り（「確定」と対）。
- 推奨：閉じる系はデザイン部品（YoseComponents の既定）に合わせて **「とじる」に統一**（部品既定が「とじる」・用例が多い）。ただし本文の地の文は漢字なので、ボタンだけひらがな方針なら「戻る→もどる」も揃える。逆に漢字へ寄せるなら YoseComponents:10 も「閉じる」に変更。どちらでも良いが **1か所の既定で決める** のが要点。ShopView:109 は「元に戻す」と読めるよう「戻す」(ShopView:159 と同形)に寄せると意味が分かれる。

## §2 とばす／スキップ（重要度：中）
| 形 | 場所 |

| とばす ▶ | IntroFlow:53（closeTitle） |
| スキップ ▶▶ | FinalsBroadcastIntro:83, :578、YoseChampionCelebrationView:205（見た目）。a11y ラベルは「スキップ」 |
| スキップ | TournamentResultView:215、accessibilityLabel 2か所 |

- ゆれ：同じ「演出を飛ばす」で 3 語（飛ばす2／とばす1／スキップ 4〜5）。記号も なし／▶／▶▶ の3通り。
- 推奨：**「スキップ」に統一**（最多・a11y ラベルが既に「スキップ」）。記号は ▶▶ か なし のどちらかに（▶▶ は「早送り」の意味でスキップに合う。小さい補助ボタンは記号なしでも可）。IntroFlow は YoseComponents 経由なので closeTitle を渡す側で「スキップ ▶▶」にする。

## §3 次へ進む系と ▶ の付け方（重要度：中）
| 形 | 場所 |
|---|---|
| 次へ 進む ▶（半角スペース） | ChoiceEventOverlay:249、TournamentResultView:174 |
| 次の声へ ▶ | TournamentResultView:213 |
| タップで進む ▶ | YoseChampionCelebrationView:205 |
| タップで進む（▶なし） | S6bView:190 |
| タップで次へ（▶なし） | QualifierNoticeView:138 |
| 画面をタップして進む ▶ | YoseMilestoneFX:135 |
| 画面をタップして閉じる ▶ | YoseRankUpOverlay:99 |
| 通知をタップ（▶なし） | QualifierNoticeView:99 |
| つづける（▶なし） | QualifierNoticeView:143 ほか Text 2 か所 |
| 本番へ ▶／最後の舞台へ上がる ▶／タイトルへ ▶／もう一度 ▶ | StageViews:332、S6bView:126、EndingViews:417 / :91 |
| 次の組を見る ▶／次の講評へ ▶／順位ボードへ ▶／後の組を見る ▶／舞台へ ▶ | FinalsPresentationView:314-319 |
| 次の審査員札をめくる（n/7）▶ | FinalsPresentationView:1019 |
| 次の週へ ▶／結果を見る ▶／{n}年目へ ▶ | FinalsPresentationView:1141、YearResultView:433 |

- ゆれ1：「次へ 進む」は「次へ」と「進む」を並べた重言＋途中に半角スペース。同種の進行ボタンは「次へ ▶」か「進む ▶」の1語（例「次へ ▶」）で足りる。2か所なので直しやすい。
- ゆれ2：タップ誘導の文が4形（タップで進む／タップで次へ／画面をタップして進む／画面をタップして閉じる）。▶ の有無も混在（S6b と Qualifier は無し、他は有り）。
- ゆれ3：ボタン内の ▶ はほぼ付いている（行先を示す語＋▶）が、「つづける」「スキップ」(TournamentResult)「閉じる」は無し。これは「主ボタン＝▶あり、閉じる系・補助＝なし」の意図に見える。
- 推奨：タップ誘導は **「タップで進む ▶」** に統一（短く、最多形に近い）。閉じる誘導は「タップで閉じる ▶」。主ボタン（行先つき）は ▶ あり、閉じる／スキップ補助は記号なし、をルール化。「つづける」は「続ける」とも書かれうる。UI 内は ひらがなで統一済み（1 形のみ）。
- 記号の種類：▶ のほかに ▲▼（RentStatement:99「足りない ▲」＝不足の意味、YearResultView:45「▼ 下にも続きます」＝スクロール案内、NetaSelectionView:62「とじる ▲／ネタを選ぶ ▼／変更 ▼」＝開閉）。意味が違うので使い分けは妥当。ただし ShopView の開閉などで「▼」が付かない同種の開閉部品があれば要確認（WeekMainView:725 の「とじる／替える」は ▲▼ なし → NetaSelectionView:62 とは不揃い）。

## §4 「無い／ない」の表記（重要度：低）
| 形 | 場所 |
|---|---|
| 無い | NetaSelectionView:34「——まだ、ネタは無い。」、:36「ほかにかけるネタが無い」 |
| ない | NetaSelectionView:100「持ちネタがない」、NotebookView:223「記録はない」、:303「ネタがない」、WeekMainView:898 / :975「時間がない」 |
| 足りない | WeekMainView:1061-1063、RentStatement:99 |

- ゆれ：同一画面（NetaSelectionView）の中で 無い(2)／ない(1)。全体では ない 5、無い 2。「出来る／できる」は部品内に「できない」系のみで、漢字の「出来る」は無し（YearResultView:252「出来事」は別語）。
- 推奨：**「ない」（ひらがな）に統一**（多数派・やわらかいトーン）。NetaSelectionView:34,:36 の 2 か所だけ。ただし「——まだ、ネタは無い。」は地の文寄り（ダッシュで始まる空状態の語り）なので、台詞扱いで残す判断もあり。

## §5 押す／タップ（重要度：低）
- 「押す」：ShopView:45「値札を押すと買えます」、WeekMainView:903 / :1056 / :1579 / :1598「もう一度押すと…」、IntroFlow:611「押せます」。
- 「タップ」：QualifierNoticeView:99,:138、S6bView:190、各 FX（§3）。
- ゆれ：ボタン操作は「押す」、画面全体への操作は「タップ」の使い分けになっており、**意図的な使い分けと読める**（部品＝押す、画面＝タップ）。ただし ShopView:45 の「値札を押す」は値札が札型の部品なので適切。揃える必要は低い。補足：二度押し確認の文が「もう一度押すと、このオファーを受ける。」（トースト・句点あり）と「もう一度押すと受ける」（札内・読点なし短縮）で語尾が違う（§7）。

## §6 スペース（全角／半角）（重要度：中）
| 形 | 場所 |
|---|---|
| 全角スペース（年と週の間） | 「1年目　第1週」IntroFlow:580、WeekMainView:341、CalendarView:47、TournamentResultView:134、YoseYearTurnCurtain:221 |
| 半角スペース（年と後続の語） | 「{n}年目 年末総決算」YearResultView:26、「{n}年目 ・ 年次リザルト」:182、「第n週 {カテゴリ}」CalendarView:118 |
| 全角スペース（字間・名札） | 「自　分」「相　方」「目　標」IntroFlow:563-583、「寄　席」EventBackgrounds:1412 |
| 半角スペースで字間（見出し） | 「練 習 大 成 功」「番 付 昇 格」「千 秋 楽」「新 シ ー ズ ン 開 幕」「漫 才 の 頂 、 こ こ に 決 ま る」 |
| 半角2つ | 「最終決戦  ——  4票先取」「審査員席  7名・1人100点満点」（FinalsPresentationView／FinalsBroadcastIntro:155） |
| ・区切り（前後半角） | 「週 ・ 賞金」CalendarView:47、「体力が足りない ・ 休もう」WeekMainView:1061 |

- ゆれ1：年＋週表記は「N年目　第W週」（全角、4か所）が多数派。YearResultView の「N年目 年末総決算」「N年目 ・ 年次リザルト」は半角＋「・」。CalendarView:47 は全角と「 ・ 」が1行に混在。
- ゆれ2：字間を空ける見出しは、全角空け（2字の名札）と半角空け（4字以上の演出見出し）で分かれる。2字は全角、長い見出しは半角で、目的（等幅に近い字間）が違うので **意図的**。ただし半角空けが「（）」や読点に飛び火している（「漫 才 の 頂 、 こ こ に…」）点は見た目の確認のみ。
- ゆれ3：「審査員席  7名」「最終決戦  ——  4票先取」の半角2連続は Text 内で潰れて見えることがある（HTML でなく SwiftUI なので潰れはしない）。
- 推奨：年・週表記は **全角スペースの「N年目　第W週」に統一**し、区切りの「 ・ 」は CalendarView:47・YearResultView:182・WeekMainView:1061 の3か所を共通ヘルパーにするか、全角「・」の前後スペースなしに揃える。優先度は低〜中。

## §7 句点「。」の有無（重要度：中）
| 部品の種類 | 句点あり | 句点なし |
|---|---|---|
| トースト（showToast 6 件） | 5（WeekMainView:903,1490,1499,1506,1579） | 1（CalendarView:118 は「…。」と付いている＝実質6/6あり） |
| 札内の説明文（desc／補助行） | WeekMainView:1450 付近の用語、SettingsView:216、ShopView:25 など文章形は句点あり | 「もう一度押すと受ける」(WeekMainView:1056)、「今週は撮影で練習できない」(:1061)、「体力が足りない ・ 休もう」、「値札を押すと買えます」(ShopView:45)、「名前を書くと「結成する！」が押せます」(IntroFlow:611)、「空欄ならおまかせ命名」「経験点が残ってる。能力アップで使おう」(WeekMainView:471：途中のみ) |
| 同じ内容の短縮 | トースト「今週は撮影。稽古の時間がない。」(WeekMainView:898) | 札内「今週は撮影で練習できない」(:1061) |
| 空状態の文 | 「まだネタがない。「ネタを書く」から書こう。」 | 「持ちネタがない」「選んでいない」(NetaSelectionView:100) |

- 傾向：**トーストは全て句点あり**（揃っている）。**札・補助行・ラベル（12pt 前後の1行）は句点なし**が多数派。文を2つ以上持つもの（途中に句点があるもの）は末尾にも付ける。すなわち「トースト＝文（句点あり）、札内ラベル＝体言止め／1行（句点なし）」の使い分けは概ね守られている。
- 目立つ例外：①WeekMainView:471「経験点が残ってる。能力アップで使おう」は 2 文なのに末尾の句点なし（同じ画面のトーストは 2 文なら末尾あり）。②IntroFlow:611・ShopView:45 は 1 文の案内で句点なし（札内のため妥当）。③CalendarView:118 のトーストは「第N週 カテゴリ。」と体言的な短文に句点を付けている（トーストは全部句点ありのルールに従っている）。
- 推奨：トースト＝句点あり（現状維持）、札内1行ラベル＝句点なし（現状維持）。例外は WeekMainView:471 に末尾「。」を足すか、2文を1文に縮める（例「経験点が残ってる。能力アップへ」）。
