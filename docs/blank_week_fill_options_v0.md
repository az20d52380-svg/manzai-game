# 空白週を埋める案 v0（材料まで・決めるのはオーナー・コード未変更）

根拠：docs/blank_weeks_measure_v1.md 結論（空白は年内12〜18週目から最長10〜12週・イベント率を上げても1週未満しか縮まない）と fun_audit_v0 §3-3（台詞・演出・節目で解く）。数値はすべて【仮】。

## §1 今ある「週ごとに少し何かが起きる」仕組みの棚卸し
| 仕組み（場所） | いつ出るか | 空白週に出るか |
|---|---|---|
| 週頭の掛け合い weekBanter（GameSession.rollWeekBanter／DialogueData.banter） | 週頭に抽選。基礎30%、次の本番が6週以上先なら55%。選択イベントが立つ週は譲る。帯は plain/lull/eve/streak/broke/afterPass | 出る（空白帯 lull 用の帯がある）。ただし毎回ではなく約半分 |
| 独白 innerVoice（DialogueData.innerVoice／monoBox） | 毎週、状態の優先順で1行（療養>体力>金欠>負け>通過>本番2週前>遠い本番=midseason>平常）。掛け合いが出た週は掛け合いが優先 | 出る。空白中は midseason／平常の使い回しになりやすい（同じ行の再出が単調さの元になりうる） |
| WeekHint（WeekHint.swift） | 毎週、条件に当たる時だけ1行（借金・ネタ無し・生活費・体力・相方と話していない・経験点） | 条件次第。健康で金があると何も出ない週が多い |
| 行動の一言 resultLine（WeekMainView.makeResultLine） | 行動後に「所持金／経験点／体力」の差分を1行。台詞ではなく数字の帯 | 毎週出るが数字だけで物語がない |
| 選択イベント ChoiceEventData（36種・原則1回・EventScene 7場面） | 条件を満たした自由週に抽選。上限あり | 抽選が空振る週が約半分（測定どおり） |
| ファンレポ FanReportData | 大会の結果画面のみ（ヒトコエの声） | 出ない（大会が無い） |
| 季節の催事（summerFestivalGig 等） | 特定の週・条件のイベントとして | 年1つ程度。空白帯に置かれてはいない |
| オファー（activeOffer／offerCard） | 条件で週の帯に出る | 空白の定義上、オファーがある週は空白でない |
| お店（ShopView） | 自分で開く。週の出来事ではない | 出ない（能動のみ） |
| 稽古の稼ぎ表示・週の演出（Juice／StageScene） | 毎週 | 毎週同じで変化が少ない |

要点：声は毎週あるが、(a)空白帯で使える掛け合い・独白の本数が少なく繰り返す、(b)カレンダー上に「この週は何かある」という目印がない、(c)行動の結果が数字だけ、の3点が空白の体感を作っていると見える。

## §2 案（7本）
共通の守り：キャラ会話にお笑い要素（ボケ・オチ）を入れない／％を出さない／実在名禁止（manzai-drama-voice v3）。台詞本文は未作成（例は1行のみ）。

**案A 空白帯専用の掛け合いを増やす（lull プール拡張）**
- 様子：本番が遠い週、週頭に谷口と俺が日常の短い会話（部屋・食事・天気・昔の話）を交わす。
- 既存：weekBanter／.lull 帯。出現率55%は据え置きでも体感が変わる。
- 新しい文：2〜3行×30組＝約80行。
- 数値：触らない（UI乱数の消費のみ、golden非干渉）。
- 手間：小（文のみ）。
- 決まり：会話はお笑い要素なしの日常描写に限定すれば適合。例「谷口：今日は風が冷たいな」。

**案B 空白期の独白を週番号で回す（midseason／平常を増やし、連続で同じ行を出さない）**
- 様子：同じ週画面でも、季節・何年目かに応じて俺の一言が変わる。
- 既存：innerVoice の pick（直近回避あり）。
- 新しい文：季節別（春夏秋冬）各10行＝約40行。
- 数値：触らない。手間：小。決まり：適合（独白はボケない）。

**案C 月初の小さな節目（劇場の査定・先輩の舞台・客の反応）をカレンダー上の目印にする**
- 様子：空白帯に「月1」の節目週を置き、見ると一言のカード（劇場の人の一言、客席の一人の感想）が出る。ゲーム内の効果は無し。
- 既存：EventScene（gakuya・office 等）の演出枠を流用、ChoiceEventData の「選択肢なし」型。fun_audit §3-3 案1そのもの。
- 新しい文：節目10〜15種×3〜5行＝約50〜70行。
- 数値：触らない（効果無しの専用プールなら帯は動かない。測定の副作用欄が推奨する形）。
- 手間：中（イベント表＋抽選条件＋表示）。決まり：客の反応は「ボケない・％なし」の感想に限る。

**案D 行動の一言を物語の一文に変える（稽古後の手応え・場面の一言）**
- 様子：「所持金 −3,000　経験点 +2」の数字の帯に、1行の地の文（手応え・稽古場の様子）を添える。
- 既存：makeResultLine（数字は残し、頭に文を足すだけ）。fun_audit §3-2 の「手応え」案と共通。
- 新しい文：行動9種×4〜5行＝約40行。
- 数値：触らない（表示のみ）。手間：小〜中。決まり：地の文なので適合。

**案E 空白帯に「週の便り」ミニ枠（ヒトコエ風の街の声・劇場だより）**
- 様子：大会が無い週でも、画面下に架空SNSの観客の声が1枚だけ流れる（コンビを知っている人の独り言）。
- 既存：FanReportData の枠とデザインを流用（今は大会の結果画面限定）。
- 新しい文：知名度帯ごと約30行。
- 数値：触らない。手間：中（出す場所の新設）。
- 決まり：実在名禁止（架空SNS名のまま）、％は出さない、感想は褒め・ぼやきの日常語。ボケの引用は避ける。

**案F 季節の催事の追加（桜・梅雨・夏祭り・文化祭・年末の挨拶）**
- 様子：年内の空白帯（12〜18週目あたり＝梅雨前後）に季節の小イベントが入る。選択肢は1〜2つで効果は小さな金・体力のみ、または無し。
- 既存：summerFestivalGig に倣った ChoiceEventData。
- 新しい文：1イベント約8〜12行×6〜8本＝約60〜90行。
- 数値：効果ありだと帯に触る恐れ（測定の副作用欄）。効果無しなら触らない。手間：大（イベント条件・発火上限との整合）。
- 決まり：適合（会話はボケない）。

**案G WeekHint を空白帯用に足す（次の山場までの目安・稽古の理由）**
- 様子：何も出ない週に「次の舞台まであと◯週」「今週は◯◯を磨く週」の案内の一行を出す。
- 既存：WeekHint の優先順の末尾に1条件。fun_audit の「次の山場まであと◯週」。
- 新しい文：案内の定型10行ほど。
- 数値：触らない。手間：小。決まり：週数は出してよい、％・見込みは出さない。

## §3 推奨順（効き目÷手間）
1位：案A＋案B（文だけ・小・既存の抽選枠に載る）。続けて案G（さらに小）で空白帯の声を毎週に近づける。
2位：案D（地の文を添えるだけで毎週の手応えが上がる）→ 案C（目印のある月1の節目＝fun_audit の推奨）。
3位：案E（出す場所の新設が要る）、案F は効果なしの節目として C に統合するまで後回し。数値を動かす案は不採用のまま。

## 判断が要る点（オーナーへ）
- 案C・F の節目に「効果を付けるか（付けるなら規律Aと再実測）」。推奨は付けない。
- 空白帯の掛け合い率を55%から上げるか（UI定数のみ・数値に非干渉）。
