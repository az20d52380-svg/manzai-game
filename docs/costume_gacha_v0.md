# 衣装ガチャ 設計案 v0（2026-10-20・コードは触っていない）

> **【10/20 オーナー決定で上書き】** 無料で回す分は**ログインボーナス**（毎日もらえる物を貯めたら1回）。大会・年替わりの無料券（§2）は使わない。最初に持っている衣装は1着だけ。**初回ガチャ**を付ける（中身は未定）。


オーナー決定（10/20）：衣装は見た目だけ（強さに効かない）・買ったら周回をまたいで残る・ガチャにする（無料の券でも有料でも回せる・安い）。広告カット1,000円（衣装1着付き＝ガチャの外の1着）。個人事務所600円。遊ぶ画面に％は出さない。
※値段・枚数・確率はすべて【仮】。決めるのはオーナー（§5）。

守り方（案）
1. 確率は「提供割合」の別ページ（設定→購入の中）に出し、ガチャ画面からリンクを置く。遊ぶ画面（ホーム等）には出さない。Apple の「買う前に見える」はこのリンクで満たす（ガチャを回す確認ダイアログの直前に「提供割合を見る」ボタン）。
2. コンプなし：全部そろえてもおまけ衣装は出さない。「そろえたら◯◯」と書かない（景表法）。
3. 天井：かけら交換で好きな1着が確定（§2）。使い込みの安全弁にもなる。
4. 割合を変えるなら予告（版を上げて告知）。
5. 未成年：端末側の「ペアレンタル／購入制限」とApple の購入承認に任せる。ゲーム側で月額上限を持つかは任意（§5 Q3）。1年の最大購入額が小さいので自前の上限は後回しで足りる。

## §2 形の案
### 値段（推奨＋安い案＋高い案）
| 案 | 1回 | 10回 | 好きな1着が確定する額 |
|---|---|---|---|
| 安い | 60円 | 600円 | 約2,400円（40回） |
| **推奨** | 100円 | 1,000円 | 約4,000円（40回） |
| 高い | 160円 | 1,600円 | 約6,400円（40回） |
商品は消耗型2つ（「券1回」「券10回」）。10回は割引なし推奨（景品の「おまけ」感を出さない／まとめ買い誘導を弱める）。割引ありなら11回。

### 無料の券（仮・1年目の目安）
- 大会で勝ち進む：予選通過1・準決勝1・決勝進出1・優勝2＝最大5枚（負けた所までの合計）。
- 年替わり：新しい年を迎えるたび2枚。
- ログイン等の毎日配布は推奨しない（毎日開かせる圧になる）。
- 1年目の目安：大会フルで勝てば約7回、早く負ければ約3回。3年で約15〜20回。→ 無料だけで普通は1〜2着、通しで遊べば天井（40回）には届かず、有料の背中押しになる設計。
- 無料券と有料券は別の残高にして、無料券から先に使う。

### 被りの救いと天井
- 被り→「かけら」に変わる：色替え1・柄2・特別5。
- かけら交換：色替え10・柄20・特別40。かけらに加え、回すごとに「天井ポイント」1。40ポイントで好きな1着と交換（特別も可）。確定までの回数＝40回（有料なら約4,000円）。
- 持っていない衣装を交換先に選べる。全部持ったら、かけらは「記念の称号」などに回すか使い道なし（§5 Q3 の外。決めずに置ける）。

### レア度（推奨：3段、色は目安）
| 段 | 中身 | 着数 | 提供割合（仮） |
|---|---|---|---|
| 色替え | スーツの色違い。いちばん普通 | 5 | 60%（1着あたり12%） |
| 柄 | 柄・和装のような見た目の違い | 4 | 30%（1着あたり7.5%） |
| 特別 | 全身が変わる／小物付き | 3 | 10%（1着あたり約3.3%） |
※％は提供割合ページ用。遊ぶ画面には出さない。10回に1回は柄以上、のような「確定枠」は付けない（割合表示が複雑になる）。

## §3 衣装の一覧（発売時12着の案・名前は仮）
無料の既定「標準」（今の青×赤）は別枠＋広告カット付きの1着（ガチャの外）＝「黒紋付（くろもんつき）：黒に白い家紋。漫才の正装」。
| 段 | 名前 | 見た目の一言 |
|---|---|---|
| 色替え | 紺スーツ | 落ち着いた紺。ネクタイは細め |
| 色替え | グレースーツ | 銀ねず。少し古い劇場の雰囲気 |
| 色替え | 小豆スーツ | 暗めの赤茶。稽古場帰りのよう |
| 色替え | 若草スーツ | 明るい緑。若手の勢い |
| 色替え | からし色スーツ | くすんだ黄。目立つが下品でない |
| 柄 | ストライプ | 細い縦縞で寄席の定番 |
| 柄 | チェック | 大きめの格子。ちょっとおどけた感じ |
| 柄 | 柄シャツ | ジャケットなしの派手な総柄 |
| 柄 | ジャージ | 上下そろいの運動着。ライン入り（稽古場感） |
| 特別 | 袴（はかま） | 紋付に袴。和の正装（今の hakama を転用） |
| 特別 | 豹柄 | 全身の派手柄。舞台で目立つ（今の leopard を転用） |
| 特別 | きらきらジャケット | 銀ラメの舞台衣装。小物は蝶ネクタイ |
実在のコンビの衣装は避ける（赤いジャケット等の特定の組み合わせ、ファミリー衣装に寄せない）。上は色・柄の一般的な意匠のみ。

## §4 今のコードとのつなぎ方（確認済み）
現状
- StoreIDs.swift：商品IDを集約。adFree・agency は非消耗型。`costume(name)` は「1着ずつ非消耗型の商品」＝今は hakama・leopard（仮120円）だけ。
- StageOutfit.swift：`enum StageOutfit: String, CaseIterable`（standard/hakama/leopard）。`current` は UserDefaults の "stage_outfit" を読み、未所有なら standard に戻す。所有の判定は `StoreManager.shared.owns(StoreIDs.costume(...))`＝購入履歴頼み。色は `ore(rival:)` と相方側で case ごとに定義。
- StoreManager.swift：`purchase(id)` は成功後 `owns(id)` を返す＝非消耗前提。`updateEntitlements` は `Transaction.currentEntitlements` を見るだけで、消耗型は含まれない。

ガチャに変えると変わる所
1. 衣装は「購入したか」でなく「ガチャで出たか」で持つ。所有の保管は端末内（UserDefaults/Keychain 等）＋ iCloud が要るか検討。消耗型は復元できず、機種変更で衣装が消えるため。→ 判断が要る（§5 Q2）。
2. 追加する物（決めずに作れる）
   - `StageOutfit` を12着+標準+黒紋付に拡張、`Rarity`（色替え/柄/特別）、色定義（見た目）。
   - 新規 `GachaState`（所有衣装集合・券の残高（無料/有料）・かけら・天井ポイント・回した回数）を保存。ガチャの抽選は「割合の表」を1か所に置き、提供割合ページはその表から生成（食い違い防止）。
   - 抽選・被り変換・かけら交換・天井の純ロジック＋テスト（乱数は差し替え可能に）。
   - 提供割合ページ、ガチャ画面、結果表示、着替え画面（`StageOutfit.current` の所有判定を新しい保管へ差し替え）。
   - 無料の券の付与（大会結果・年替わりのイベントに1行ずつ）。
3. 判断が要る部分
   - 有料券を StoreKit の消耗型2商品にする（StoreIDs に ticket1・ticket10 を足し、`purchase` を消耗型対応＝購入成功で券を足してから finish）。受け取り前に落ちた場合の再付与は `Transaction.updates` で拾う。→ 値段と所有の保管場所が決まってから。
   - 既存の hakama・leopard の非消耗商品は廃止（未発売なら消すだけ）。発売済みだと既購入者へ配る必要。→ 未発売かの確認が必要。
   - Configuration.storekit の商品差し替え（iap_design_v0.md §1 が正本。ここも直す）。

## §5 オーナーに聞く事（最大3問）
Q1. 1回の値段と、好きな1着が確定するまでの回数（天井）をどうするか。
- 推奨：1回100円・10回1,000円・40回で好きな1着（約4,000円）。
- 理由：衣装は見た目だけなので高くしにくく、他のゲームの感覚（1回100〜300円）より安め。天井が低いほど安心して回せ、審査でも説明しやすい。

Q2. 機種を変えても衣装が残るようにするか（アップルの保管に預けるか）。
- 推奨：残す（iCloud に預ける）。
- 理由：消耗型の券は復元できず、「ずっと残る」という決定を守るには保管を iCloud 側に持つ必要がある。残さない場合は「機種変更で消える」と購入画面に書く必要がある。

Q3. 無料の券の配り方はこれでよいか（大会で勝ち進む＝最大5枚・年替わり2枚・毎日配布はしない）。
- 推奨：この案。
- 理由：遊びの進みに合わせて少しずつ増え、毎日開く圧が出ない。1年目で数回しか回せないので、有料を押しつけない程度の「お試し」になる。
