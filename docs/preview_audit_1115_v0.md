# 行動カードの「効果の見込み」と実際の食い違い 静的点検 v0 / 2026-11-15

読むだけ（コード・ビルド・シミュレータ非接触）。対象：GameSession.previewState/previewAfterPour（GameSession.swift:466-510）・WeekMainView の札（actionCardLabel :1063-1170／cardEffects :1561／netaEffectText :1597）と、実際の WeekRunner.resolveAction（:325-370）・applyNetaWork（GameSession.swift:845-885）。

## 要点
1. 新規 5件（中2・低3）＋既出の確認 5件。見込みの数字そのものは、借金の半減・部屋の加算・道具・スキル（愛され芸人）・相性凍結・テレビ慣れまで「state の写しに同じ apply* を当てる」ので実際と一致する（乱数の絡む体調ダウンだけが名目値）。
2. 最も重いのは **N1（お金が足りない有料の稽古・休みの札から値段が消える）**。「お金が足りない」とだけ出て、いくら要るのか札のどこにも出ない（払えない時の休みへの差し替え見積もりで所持金の差が0になるため）。
3. 次点 N2：休みの「体力 +60／+100」は上限100を無視した名目値で、実際の回復より大きい（有料の温泉6万円で体力70→「+100」・実際 +30）。

## 節構成
§1 観点1：見込みに入っていない補正の一覧／§2 観点2：「+n」と出て実際0／§3 観点3：押せない札の見た目／§4 観点4：丸めの食い違い／§5 新規の指摘（N1〜N5）／§6 既出の確認／§7 問題なしと確かめた所

## §1 見込みに入っていない補正（観点1）
前提：previewState は state のコピーに applyTraining/applyJob/applyRest/applyOffer を当てるだけ（RNG非消費）。次は「入っている」。
- 借金中の稽古半減（debtTrainFactor）：applyTraining 内で state.money<0 を見る＝入っている（粒の数字は半分で正しい）。札に理由の一言は無い＝既出 money_audit M4。
- スキル：愛され芸人（知名度×1.1）は add() 内＝入っている。体が資本（体調ダウン確率×0.7）・相方思い（すれ違い）は札と無関係。
- 道具：ICレコーダー・稽古場の年契約・銭湯の回数券は applyTraining/applyRest 内＝入っている。
- 部屋の休み加算：applyRest 内で入り、体力の数字は View が同じ式を書き直している（:1069-1075。N2 参照）。
- 相性凍結：add 内で止まるので、凍結中は「相性 +n」の札が出ないだけ。ただし現行の選択肢イベントは凍結を使わない（ChoiceEvent.swift:204「compatFreeze は使わない」）＝実際には到達しない。
- テレビ慣れ（センス・表現 −0.5）：applyOffer に atWeek を渡して入っている（GameSession.swift:476）。ただし減る方は札に出ない（実力 ↑ は増える時だけ・:1563）。説明の帯は DEBUG の環境変数だけ＝既出（decision_brief_2026-10-25・AUTOPILOT 112/137・code_review_2026-10-19b）。
入っていない（実際だけで起きる）：
- 体調ダウン（体力<50 の稽古・キツいバイトで確率 (50−体力)×0.5%・×0.7 or 喉ケア）：名目値の外＝既出 stamina N1（事後の表示）。事前の予告は札に無い（N4）。
- 体力ゲートの休みへの差し替え：札をグレーにして実害を消している（:917）。
- ネタ合わせブースト（書けた一本）の ×1.6 と完成度100の頭打ち：既出 neta N5。
- 週末の生活費・すれ違い：名目値として除外（コメントに明記）。生活費は WeekHint が「今週末に生活費…所持金が足りない」と別に出す。

## §2 「+n」と出るのに実際は0（観点2）
- 完成度 +8／+12／+6：対象ネタが完成度100（実際 0〜端数）。見込みは対象ネタの現在値を見ない＝既出 neta N5（上限の件）。
- 休みの「体力 +n」：体力が満タンでも +60 と出す設計（:1068 のコメント）。満タンで押すと実際 0＝結果の札は出ない。N2。
- 経験点 +n・相性 +n・知名度 +n：state の差から出すので、実際と一致（0 になる経路は無し）。
- 「実力 ↑」（オファー：表現+2）：テレビ慣れで同時に センス・表現 −0.5 が入っても、純増なら出て、純減なら消える＝既出の枠（テレビ慣れ）。

## §3 お金・体力が足りない札の見た目（観点3）
- 体力不足の稽古：グレー地・グレー文字・朱の「体力が足りない・休もう」・伸びの札を消す（:917・:1066）。押すと横ブレ＋「体力が足りない。今日は休もう。」。問題なし。ただし値札の側は N5。
- お金が足りない稽古・休み：グレーにならず、押せる札と同じ地色・同じ名前の色。違いは朱の一行「お金が足りない」だけ（:1097）。押すと横ブレ＋トースト。N1・N3。

## §4 丸めの食い違い（観点4）
- 体力（稽古・バイト・オファー）：札 `Int(after.rounded()) − Int(before.rounded())`（:1068）と結果 `lastStaminaDelta`（GameSession.swift:408）は同じ丸め＝一致。休みの札だけ上限を無視（N2）。
- 相性：札 :1565 と結果チップ :1333 は、今は両方「前後を丸めて引く」＝一致（number_display #1 は反映済みを確認）。
- 知名度：札 :1569・結果チップ :1345 は両方「増分を丸める」＝札と結果は一致。バー（値を丸める）とだけ揺れる＝既出 number_display #2。
- 経験点：札 `ExpDisplay.value`（切り捨て・×10）・結果行 `ExpDisplay.total`（各通貨の切り捨ての合計）＝同じ規則で一致（札の2通貨の和 = 結果の合計）。
- ネタ：札「完成度 +\(Int(gain))」（切り捨て）／結果チップ「ネタ +\(Int(polish.rounded()))」（丸め）。現行の値は整数なので一致。ブースト時は ×1.6（12.8→「+13」）で札と合わない＝既出 N5。言葉も「完成度」と「ネタ」で違う（N6）。
- 所持金：札は `after.money − s.money`（整数）。結果は `st.money − before.money + 生活費`＝一致。

## §5 新規の指摘

### N1 【中】お金が足りない有料の稽古・休みの札は、値段が消えて「お金が足りない」としか出ない
- 場所：WeekMainView.swift:1065-1067（after・moneyDelta）／:1124・:1138・:1144（`if moneyDelta != 0 { costPill(… insufficient: !v.affordable) }`）／GameSession.swift:466-471（previewState：払えない稽古は完全休養に差し替えて見積もる）／GameEngine.swift:152-154（払えない有料の休みは完全休養）。
- 起きる手順：所持金 5万円で「練習」を開く→「エントリーライブに出る」「大喜利ライブに出る」「カラオケボックスで声出し」「ネタ見せ会」（各8万円）、または「休む」の「サウナ」（1万円・所持金が1万円未満の時）「温泉に一泊」（6万円）。
- 見えること：札に「お金が足りない」（朱）だけ。見込みは休養に差し替わるので所持金の差が0＝値札が出ない。`costPill` に `insufficient:` の見た目（朱地）が用意されているが、稽古・休みの札では到達しない。いくら貯めれば押せるのか分からない。
- 既出か：no（code_review_2026-10-19j は同じ差し替えの「体力 +N」を消した件。値札は触れていない）。
- 直し案：①`!v.affordable` の時は、見込みの差でなく設定の費用（`config.trainings[t].cost`／`config.restCosts[r]`）から値札を出す（朱地の insufficient 表示）。②「あと¥◯」を出す（ショップの引っ越し札と同じ言い方）。表示のみ・golden不変。

### N2 【中】休みの「体力 +N」が上限100を無視した名目値（実際の回復より大きい）
- 場所：WeekMainView.swift:1068-1076（`stamDelta = Int((rec + roomHeal + ticket).rounded())`）／実際は GameEngine.add の `clamp(stamina+amount, 0, 100)`。
- 起きる手順：体力 70 で「温泉に一泊」（6万円）→札は「体力 +100」。実際は +30（結果チップ「体力 +30」）。体力 50 で「家で寝る」→札「+60」・実際「+50」。満タンなら札「+60」・実際は何も出ない（コメントでは意図＝「満タンでも数字で見せる」）。
- 影響：お金を払う休み（サウナ+80／温泉+100）で、払う価値の見積もりが実際より大きく見える。結果の札は実際の差なので、押した後に数字が小さくなる。
- 既出か：shop_audit #3（回復ドリンクの捨てられる分）は別物。no。
- 直し案：①`min(上の式, 100 − 体力)` で上限を反映する（満タン時は代わりに「体力は満タン」を出す＝今の「相性 +」の朱枠の考え方と揃う）。②現状維持（満タンの時の見せ方だけ守り、途中まで回復する時は上限を反映）。判断はオーナー（表示のみ）。ついでに、式の重複（:1069-1075 は applyRest の書き直し）は previewState の体力差を使えば部屋・回数券の変更で食い違わなくなる。

### N3 【低】お金が足りない札が「押せる見た目」のまま（体力不足の札はグレー）
- 場所：WeekMainView.swift:918（blocked = gated || !affordable）／:1148（グレー地は gated だけ）／:1087（名前の色も gated だけ）／:1078-1081（アイコン箱の色も gated だけ）。
- 起きる手順：N1 と同じ。体力不足の札はグレー地・グレー文字・グレーのアイコン箱だが、お金不足の札は有効な札と同じ色で、朱の一行と（出れば）値札だけが違う。押すと横ブレ＋トースト「お金が足りない。」（押せない触感は付いている）。
- 直し案：①お金不足も同じグレー地・グレー名前にする（朱の一行は残す）。②今のまま（朱の一行で足りるとする）。表示のみ。

### N4 【低】体力21〜49の稽古・キツいバイトに、倒れる危険の予告が札に無い
- 場所：WeekMainView.swift:1066（札は通常の効果を出す）／WeekRunner.swift:337-347（体調ダウン抽選）／WeekHint.swift:52（「谷口：無理すると倒れるよ。」＝体力 < injuryWarn の週の一言）。
- 起きること：体力30でキツいバイトを押すと約10%、体力21の稽古は約14%で倒れて3週休み（実際の効果は出ない）。札は「+96,000」「経験点 +n」と祝う。週の一言は出るが、優先順で生活費・体力≦30 の文の後ろ＝体力30以下では「体力が少ない。今週は休むのも手だ。」が先に出て、倒れる話は出ない。
- 既出か：近い話＝stamina N1（倒れた後の表示）・N3（体力の線のばらつき）。札での事前予告は no。
- 直し案：①札の見込みはそのまま、体力<50 の稽古・キツいバイトの札に小さく「倒れることがある」（％なし）。②週の一言の優先を、体力≦30 の文にも「倒れることがある」を含める形に直す。③現状維持。

### N5 【低】体力不足（ゲート）の札にも、稽古の費用・体力の減りの値札が出る
- 場所：WeekMainView.swift:1065-1077・:1124-1126（値札は gated でも出る。伸びの札だけ `gated || !affordable` で消している :1066）。
- 起きる手順：体力 15 で「練習」を開く→「ネタ見せ会」は「-¥80,000」「体力 -30（朱地）」が見えるのに、押しても何も起きない（休みに差し替わる）。
- 影響：実際には払わないお金の値札が出る。押せないので実害は無いが、N1 の逆（出るべき所で消え、出るべきでない所で出る）。
- 直し案：gated の時は値札・体力の札を出さない（朱の「体力が足りない・休もう」だけ）。表示のみ。

### N6 【低】札は「完成度 +n」・結果のチップは「ネタ +n」と呼び名が違う
- 場所：WeekMainView.swift:1599-1606（netaEffectText）・:1339-1342（結果チップ）。
- 起きること：押す前「完成度 +8」→押した後「ネタ +8」。数字は（ブースト・上限が無ければ）一致。同じ物を指すと分かりにくい。
- 直し案：どちらかの言葉に揃える（文の正典は manzai-drama-voice 側＝判断はオーナー）。

## §7 問題なしと確かめた所
- 体力ゲート（<20）：resolveAction と View が同じ `config.staminaGate`・稽古のグレー化と、撮影の週（preoccupiedWeeks）の自動休養化が揃っている。
- お金が足りない稽古の押下：View が blocked で止め、押しても実行しない。仮に通っても resolveAction が休みに差し替える（previewState と同じ）。
- 払えるかの判定（稽古 `money >= cost`・休み `money >= restCosts`）は applyTraining/applyRest の `money < cost` と同じ向き（ちょうどの金額は払える）。
- 借金中の稽古半減の係数は、previewState も実際も `s.money < 0`（支払い前の所持金）で見る＝同じ。
- オファーの見込み：選んだ札（activeOffer）を perform が `chooseOffer(index: offerPick)` で渡してから実行＝見込みと実際が同じ札・同じ atWeek でテレビ慣れ込み。
- 経験点・相性・知名度・体力（稽古）の札の数字は state の差から出る＝実際の applyTraining と同じ式。
- 能力アップ（粒を注ぐ）は previewAfterPour が config.autoPourAllocation（実ゲームは false）を見る＝実際の手動注ぎと矛盾しない。
- 結果行の「体力」「所持金」は実際の差（札と同じ丸め）。結果チップは最大3枚で体力が最後に落ちるが、数字の食い違いではない。
