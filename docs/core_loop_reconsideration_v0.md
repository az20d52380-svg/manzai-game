# 根幹の再確認：何年もかけて優勝する／周回で強くなる／自分で能力を上げる（考察 v0）

2026-10-10・Opus 5.5。オーナーの指摘（4月デビュー・1年目優勝はほぼ無い・周回でトロフィー/ガチャを集めて初期を強く・パワプロ式の手動能力アップは消えたのか）を受けて、過去の設計資料とコードを突き合わせた。コードは触っていない。

## §0 結論（3行）
1. **設計はもうある。アプリに入っていないだけ。** 複数年キャリア（10年・年齢カーブ・1年目優勝は7.2万キャリアで0件）、周回のトロフィー（上限カーブの持ち上げ）、相方ガチャ（2周目から）は正典v2とシミュレーションで実測済み。だがアプリは `GameSession.swift:98` の `let year = 1  // MVPは1年目のみ` のまま＝**根幹の「何年もかけて優勝」が遊べない**。
2. **手動の能力アップは、2026-10-07 の「A 削る」（オーナー採用）で自動に切り替えた。コードは全部残っている**（`AllocationView.swift` 702行・GameCore の割り振り関数）。戻すのは軽い。ただし「自動にした理由」＝今の数値だと手動で選んでも勝敗にほぼ効かない、を同時に直さないと、パワプロの面白さにはならない。
3. 推奨の順番：**①複数年キャリアをアプリに入れる → ②手動の能力アップを戻し、選び方で差が出るようにする → ③周回のトロフィー/ガチャ**。決勝の M-1 化・会話の作り直しは見せ方の作業として、この間に挟む。

## §1 4月始まり（確定）

- ただし R2 の指摘のうち「月の表示と年末画面の文言が食い違っている所」は、4月始まりのまま表示を揃えるだけで直す。

## §2 「何年もかけて優勝」— 設計と現物の差
| 項目 | 設計（正典） | アプリの現物 |
|---|---|---|
| 年数 | 1キャリア＝最大10年前後（年齢カーブで伸びが落ちる） | **1年目のみ**（`GameSession.swift:98`）。年末の後は「もう一度」か勇退エンディング |
| 1年目の優勝 | ほぼ不可能（`career_report_v1.md:48`＝0件） | 遊びの上では同じ。ただし決勝や優勝の画面は DEBUG フックでしか見られない |
| 初回の優勝率 | やり込み 2.7%（中央値10年）／決勝到達 41.5%（`canonical_v2_spec.md` §2） | 1年しか無いので「決勝の悔しさ→翌年」が起きない |
| 翌年への持ち越し | 能力・相性・ネタ帳・知名度・所持金 | 無し |

→ **いま一番大きい穴はここ。** 見た目や決勝の演出を磨いても、プレイヤーが決勝に届くのは数年後なので、2年目以降が無いと届かない。

## §3 周回で強くなる（トロフィー／ガチャ）— 設計の要点
- トロフィー＝実績ごとに 1〜3pt、累計で**能力の上限カーブを持ち上げる**（+0.02×pt/年）。0pt→30pt で初回優勝 2.8%→21.6%（`canonical_v2_spec.md` §2-B）。
- **オーナー案「初期経験値アップ」は一度測って壊れた**：初期能力+20 だと初回優勝 2.1%→63% に暴騰。対策＝「キャリアの総予算から前借りするだけ」（序盤が速くなるが天井は同じ）で 2.8% に戻した。→ **初期経験値アップは「前借り」の形なら入れられる**。手動割り振り（§4）と組み合わせると「2周目は最初から経験点を持って始まる＝序盤の選択肢が増える」になり、相性が良い。
- 周回の手触り（実測・ボット）：やり込みで2〜3周目に初優勝圏、のんびりは12周の旅。
- ガチャ＝相方名鑑（オーディションは2周目から・SSR は相性上限+4 の贅沢品）。課金の話は別論点。
- 王者編（連覇）は 2026-07-05 にオーナー判断で廃止済み。周回の目標は「一度の優勝＋コレクション」。

## §4 パワプロ式の手動能力アップ — なぜ消えて、どう戻すか
- **経緯**：2026-07 に導入（経験点を貯めて自分で5能力に割り振る・`AllocationView`）→ 2026-10-07 の作り直し調査（`fun_uiux_overhaul_v0.md` §280）が「シミュレーションは常に自動全量注ぎで測っていて、手動で選べる差は年 +6 程度・その代わり迷う画面が1枚増える」として撤去を提案 → オーナーが「A 削る」を採用 → `2028990` で週メインを1タップにし、自動注ぎに切り替えた。
- **戻すのは軽い**：`GameSession.swift:112/131` の `autoPourAllocation = true` を false にし、週メインかネタ帳に「のばす」の入口を戻す。GameCore・golden は不変（golden は既定 true のまま測る）。
- **ただし戻すだけでは面白くならない**（撤去の理由がそのまま残る）。パワプロの割り振りが面白い理由は「選び方でできあがる選手が違い、それが試合で効く」こと。このゲームで同じにするには、**選び方の差が勝敗に出る場所**が要る。候補：
  - 審査員の好み（7人の重視軸はもう決勝の見せ札にある）を、大会ごとの採点にも効かせる
  - ネタの型と能力の相性（型7種×能力）
  - 大会の形の違い（R2：ブロック制・1対1・観客票）で、効く能力が変わる
  - いずれも**勝敗の計算に触る＝規律A**（Python 正典→Swift→golden 再生成→テスト）。オーナー判断が要る。
- 段の上がる気持ちよさ（G→F の等級）は第1便で入れた等級チップがそのまま使える。
