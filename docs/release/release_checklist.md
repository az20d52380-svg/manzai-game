# 発売までのチェックリスト（v0・2026-11-02）

> 凡例：【オ】オーナーがやる事（本人確認・支払い・契約・口座など、Claude が代行できない）／【C】Claude が作れる物・作業。
> 所要は目安（Apple の審査・本人確認は日数が読めない）。「要確認」は Apple の画面・規約で最新を見る。
> 並行できる所：手順2の待ち時間に、手順5〜6（広告・Pages）と手順7の準備（C）を進める。

## 全体の流れ（長い待ちがある順）
1 Apple Developer 登録 → 2 有料アプリ契約・口座・税 → 3 小規模事業者プログラム → 4 アプリ名の登録 → 5 広告の会社 → 6 app-ads.txt と GitHub Pages → 7 TestFlight → 8 審査・発売

## 1. Apple Developer Program に個人で登録（目安：当日〜数日）
【オ】
- Apple ID を用意（二要素認証オン）。登録は個人（Individual）で行う。年額 12,800円（要確認）。
- 本人確認（身分証の提示を求められることがある）。支払い。承認メールを待つ。
- 注意：個人登録では、App Store に出る「販売元」が**本人の氏名**になる。屋号は出せない（屋号を出すには法人＋D-U-N-S が必要）。氏名を出したくない場合の扱いはここで決める。
【C】
- なし（この間に手順5〜6の下調べと、app_store_text の確認ができる）。

## 2. 有料アプリ契約・口座・税（目安：入力30分＋Appleの確認 数日〜2週間）
アプリ内課金（広告カット・ガチャの券）を売るために必須。無料アプリだけなら不要だが、今回は課金があるので必要。
【オ】
- App Store Connect →「契約、税金、口座情報」→ 有料App契約（Paid Applications）に同意。
- 銀行口座（日本の口座）を登録。連絡先（契約・財務の担当）を登録。
- 税務フォーム（日本在住の個人は、案内に従う。米国源泉の関係で W-8BEN 相当の入力が出ることがある・要確認）。
- 状態が「有効」になるまで待つ。
- 個人事業の届出（税務署への開業届・青色申告の届）と、消費税・インボイス（適格請求書発行事業者）の登録の要否は、税理士か税務署で確認【オ】。
- 特定商取引法に基づく表記（販売業者・所在地・連絡先）の要否と出し方を確認。個人の住所を伏せる方法（請求時に遅滞なく開示する旨の表記が認められる場合がある）を調べて決める【オ・要確認】。
【C】
- 特商法表記のページのひな形を作る（住所・氏名は【未定】のまま）。

## 3. 小規模事業者プログラム（App Store Small Business Program）（目安：申請10分＋数日）
前年の売上が年間100万米ドル以下なら、Apple の手数料が15%になる（通常30%）。
【オ】
- 手順2の契約が有効になったあと、App Store Connect から申請（要確認）。承認までは30%のまま。
- 適用は、承認された会計月の翌月から。**発売前に承認されているのが理想**。
【C】
- なし。

## 4. アプリ名の登録（App Store Connect でアプリを新規作成）（目安：30分）
【オ】
- 新規 App：名前「漫才王になろう」、プライマリ言語＝日本語、バンドルID、SKU。**名前は早い者勝ちで、作った時点で確保**される（取られていたら別名が必要）。
- 先に、同名・紛らわしい名前の既存アプリと商標（J-PlatPat）を確認。
【C】
- 「漫才王になろう」について、docs/app_name_prior_use_1025_v0.md と同じ形の下調べ（検索のみ・法的判断ではない）。「漫才王」が実在の大会名・番組名と紛らわしくないかも見る。
- バンドルIDの候補、SKU の案。

## 5. 広告の会社を決める（目安：選定 1〜3日＋審査・登録 数日）
【オ】
- 広告の会社を決定（例：Google AdMob）。アカウント登録、**支払い先の情報、税務情報**。AdMob は審査があり、アプリが公開されるまで本格配信できない場合がある（要確認）。
- AdMob にアプリを登録し、**アプリID・広告ユニットID**を受け取る（秘密ではないが、チャットに貼らず、設定ファイルに入れる）。
- 「Appのプライバシー」の回答、トラッキングの許可（ATT）を出すかを決める。
【C】
- 広告 SDK の組み込み（AdProvider の実装・区切りの3箇所：大会の結果の後／年の幕間／ログボ2倍のごほうび）。広告カット購入後に出さない分岐。テスト広告での確認。
- ATT の確認画面と `NSUserTrackingUsageDescription` の文面。`PrivacyInfo.xcprivacy` の更新（収集データ・追跡先ドメイン）。
- privacy_policy_ja.md の【広告会社名】【URL】の差し替え。age_rating_answers.md の広告の項の更新。

## 6. app-ads.txt と GitHub Pages（目安：2〜3時間＋反映 数日）
広告の会社が「この広告枠は正規のアプリ」と確認する仕組み。開発者のサイトのルートに置く。
【オ】
- GitHub のアカウントで公開用リポジトリを作成し、GitHub Pages を有効にする。ルートに置くなら `ユーザー名.github.io` の形（ユーザーサイト）か独自ドメイン。プロジェクトページ（`ユーザー名.github.io/リポジトリ名/`）は、ルートに置けず app-ads.txt が読まれないことがある（要確認）。
- App Store Connect の「サポートURL」「マーケティングURL（開発者のウェブサイト）」にそのドメインを入れる（広告の会社はここのルートを見に行く）。
- 広告の会社の管理画面で、app-ads.txt の行をコピー（そのまま貼るだけ）。
【C】
- サイト一式の作成：トップ（アプリの紹介）、サポートページ、プライバシーポリシー（privacy_policy_ja.md から）、特商法表記、提供割合ページ（gacha_rates_page.md から）、`app-ads.txt`（行は広告会社の管理画面の値を貼る）。
- 提供割合ページは、コードの割合表から生成した値と一致するかを検査する作業（手で写さない）。
- `AppInfo.privacyPolicyURL`（今は nil）にURLを入れる。サポートURL。

## 7. TestFlight（目安：準備 1〜2日＋内部テスト 数日〜1週間）
【C】
- ビルド・アーカイブの準備：バージョン、ビルド番号、アイコン、`PrivacyInfo.xcprivacy`、通知の許可（使わないなら外す案）、課金の商品（広告カット・券1・券10）の登録内容（`Configuration.storekit` と App Store Connect の商品を一致）。
- スクリーンショットの用意（6.7インチ・縦・docs/store_listing_draft_v0.md §4 の構成）。
- 実機での目視チェックリスト（課金のサンドボックス・復元・iCloud・広告・機種変更の想定）。
【オ】
- Xcode で署名（Apple Developer のチームを選択）、App Store Connect にアップロード。
- 課金の商品（IAP）を App Store Connect に登録し、価格と説明を入力。審査用のスクショを添える。
- 内部テスターに自分を登録して実機で遊ぶ。サンドボックスのテストアカウントで課金・復元・iCloud の引き継ぎを確認。
- 外部テスト（任意）は、簡単な審査（Beta App Review）が入る。

## 8. 審査・発売（目安：審査 通常 1〜2日・差し戻し時は＋数日。余裕を持って1〜2週間）
【C】
- 掲載文の最終版（app_store_text_ja.md）、年齢区分の答え（age_rating_answers.md）、プライバシー回答、審査メモを揃えて流し込む文面を用意。
- 提出前の自己点検：ガイドライン 3.1.1（ガチャの確率表示・復元）、5.1.1（プライバシーポリシー）、広告（子ども向けでない・年齢区分と整合）、通知の許可の扱い。
【オ】
- App Store Connect で課金の商品を「審査に提出」、アプリのバージョンと一緒に提出。
- 配信地域：日本のみ（EU 向けにしない間は、トレーダー情報の登録は不要。要確認）。価格帯の選択（広告カット 1,000円）。
- 発売日の指定（手動リリース／承認後に自動）。リリース後、レビュー・クラッシュレポートを確認。
- 差し戻しが来たら、内容をそのまま Claude に渡す（直せる所は直す）。

## 目安の合計
最短でも **3〜4週間**（Apple の確認待ちが大きい）。余裕を見て **6〜8週間**。
- 最初に始める＝手順1（登録）と手順2（有料アプリ契約）。待ち時間が長いので、先に出す。
- 手順5〜6と手順7の準備（C）は、手順1〜2の待ちと並行できる。
- 衣装ガチャ・広告・iCloud の実装が終わる前に、手順8は進められない（審査に出すビルドが必要）。
