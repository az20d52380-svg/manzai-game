## §2 案

共通の方針：勝ち負けなし・必ずウケる・数字（％・点数）を出さない・乱数を使わない（表示専用の固定演出）。ゲーム状態（state・golden・乱数列）に触らない。標準語。

### 案(a) 回想の直後に「初舞台」（推奨）
- 入れる場所：IntroFlowView の `.reminiscence` の次に新しい段 `.firstStage` を足す（`finish()` の前）。回想3枚目＝楽屋「じゃあ、行こうか」から続けて舞台へ。
- 画面の流れ（約25〜35秒・3〜4タップ）：
  1. 暗転→ 舞台の緞帳が上がる（StageFrame `.preshow`、短い字幕「小さな劇場。最初の出番。」）。1タップで進む。
  2. 二人が出てネタ。台詞1往復だけを吹き出しで見せる（谷口のボケ→俺のツッコミ）。タップ1。
  3. 客席が「どっ」と沸く：StageFrame を `.lit` に明転、ParticleBurst＋Sound `.laughSmall`→`.cheerMid`、WaveformView(passed: true) の山。タップ不要の自動（約2秒）。
  4. 判子「ウケた」が YoseHankoStamp（isSquare）でドンと押される（StampShake・Sound `.don`/`.taiko`・Haptics.confirm）。タップ1。
  5. 一言の墨帯（StageTelopBelt）「——どっと沸いた。けれど、お客さんは十人ほどだった。」→ 1週目へ。この一言で売れない時期の苦しさの話を残す（沸いたが小さい＝次の目標）。
- 使い回す部品（grep で存在確認済み）：StageFrame（StageFrame.swift・Mode .preshow/.lit）、StageSign、StageTelopBelt、WaveformView(passed:true, burst:)、YoseHankoStamp、StampShake（NotebookView.swift）、ParticleBurst／screenShake／screenFlash（Juice.swift）、Sound `.laughSmall/.cheerMid/.don/.taiko`、ManzaiFigure（StageScene.swift）、YoseAdvanceCue。TournamentResultView の判の叩きつけ（slamFire）の作りが一番近い手本。ただし TournamentResultView は GameSession の WeekSummary に依存するので丸ごとは使わず、見せる部分だけ小さな新 View（例 FirstStageView）に写す。
- 影響：タップ＋約30秒。式・乱数・state・golden への影響なし（IntroFlow 内だけで完結・結果は何も保存しない）。「とばす」は2周目以降（`hasSeenIntro`）だけ出す＝既存の回想と同じ扱い。
- 注意：回想3枚目の最後の台詞（行こうか）と、舞台の最初の字幕の間で場面が飛ばないよう、回想の3枚目を `StageFrame .preshow` の袖の絵に差し替えるかは別途検討（見た目のみ）。

### 案(b) 1週目の行動に「劇場の飛び入り」を置く
- 入れる場所：1週目のメイン画面で、行動の並びに特別枠「飛び入りで舞台に出る」を1個だけ出す（初回のみ・消費ゼロ）。押すと案(a)と同じ短い舞台場面。
- タップ数：メイン到達後 +3〜4。部品は案(a)と同じ＋行動ボタンの追加（WeekMainView の行動リスト）。
- 良い点：自分で押す＝能動の「気持ちいい」になる。悪い点：説明ポップアップ（firstWeek）が先に出て、押す前に読み物が挟まる／押さずに別の行動を選ぶ人は一生見ない／行動リスト・体力・週の進みに触るので state に近い（式は触らない形にできるが、週を消費するかの判断が要る）。
- 判定：案(a)より事故点が多い。単独では推奨しない。

### 案(c) 名前決めの直後に1本ネタを見せる
- 入れる場所：NameEntryView の「結成」判子の直後、回想の前。コンビ名を入れた直後に「〇〇の初ネタ」を見せる。
- 良い点：入力した名前が舞台の看板に出る＝自分のものという実感が強い。悪い点：出会い（回想）より前に舞台が来て、物語の順が逆（まだ出会っていない二人がネタをする）。回想の「手、冷たいんだ」の緊張の引きも死ぬ。
- 判定：順番の矛盾が大きい。ただし「看板にコンビ名を出す」要素だけは案(a)に取り込める（StageSign の title にコンビ名）。

## §3 説明ポップアップを後ろに回す／まとめる

現状（fun_playtest_1019_v0.md §2-8）：最初の11週で5回＝はじめに（firstWeek）／生活費（living）／能力アップ（abilityUp、AbilityUpView）／能力アップの2回目／大会エントリー（entry、StageViews）。すべて OneTimeHint（初回だけ）。

- 案ア（最小・推奨）：初舞台の後に出す形は今のまま、**firstWeek を「初舞台の判子の直後」に載せ替える**のではなく、初舞台の一言の墨帯に1行だけ足す（「実力＝コンビの強さ。経験点＝能力アップに使う」）。firstWeek 本体は「？」ボタン（HintMarkButton・WeekMainView 351行）から読める形のまま、自動表示をやめる。これで1週目の最初のタップが減る。※5項目の用語（実力/相性/体力/知名度/経験点）のうち、最初の数週に要るのは体力と経験点。
- 案イ：5回を「出る場所で1行の札」に置き換える（ポップアップではなく、画面の端に1行が数秒出て消える。タップ不要）。表示だけの変更で state 不変。
- 案ウ（触らない）：説明は今のまま、初舞台だけを前に足す。タップ数は増えるが、手戻りが無い。
- 推奨：案ア→様子を見て案イ。ポップアップを消すと説明が足りなくなる恐れがあるので、いきなり全廃はしない。

## §4 オーナーに聞く事（専門語なし）

1. 何を決めたいか：回想の直後に、10〜30秒の「初舞台」（必ずウケる・勝ち負けなし）を足してよいか。
   - 推奨：足す（案a）。
   - 理由：出会い→楽屋→舞台と話がそのまま続き、2分前後で「どっと沸いた」が1回見られる。ゲームの中身（数値）は何も変わらない。

   - 推奨：少し苦くする（客は十人ほど）。
   - 理由：売れない時期の話を残すというオーナー決定に合い、次の目標（もっと大きい舞台）も自然に見える。
