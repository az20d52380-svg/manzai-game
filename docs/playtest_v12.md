# 実プレイ点検 v12（予選の知らせ・決勝進出者の発表・iPhone 17・2026-10-19）

要点：
1. 予選の結果の知らせ（QualifierNoticeView）と決勝進出者の発表（FinalistAnnounceView）は、どちらも TournamentResultView の「判の前」（本番前カード→結果画面→知らせ→開演の儀→判）に出る作り。コードの並びと目視（フック）で位置は正しい。
2. 迷う所は「飛ばす」の挙動が両画面で違う点と、知らせの後に判で同じ結果をもう一度見せる点（要・実機の通し確認）。崩れは見えず、％表示も無し。
3. 今回はタップが使えない回（無人実行）だったため、通しプレイ（予選→準決勝→発表→決勝）と各「つづける」後の遷移は未確認。

節構成：§1 見た画面とフック／§2 所見（重要度順）／§3 未確認

## §1 見た画面とフック（撮影は scratchpad・docs には3枚だけ保存）
- gpresult／qual_notice：1回戦の結果画面にロック画面の通知「【結果発表】1回戦の通過者を掲載しました」（本編どおり結果画面の上に重なる）。
- qual_notice MZ_OPEN=1：通過者9組が五十音順・自組が金で光る・下に「つづける」（docs/playtest_v12_qual_list.png）。MZ_PASS=0 は自組が無い9組・ボタンが「閉じる」。
- qual_line（準々決勝）：通知は谷口「見た？」のみ（docs/playtest_v12_qual_lock_qf.png）。MZ_OPEN=2 で「開く」→「あった！／名前、あった！！／やった……」、落選は「…………／次いこ」。
- finalist_announce：待ちの1枚「準決勝の終演から、しばらく。」→司会＋16組の並び→読み上げ（MZ_HOLD_AT）。落選側は自組が灰のまま（docs/playtest_v12_finalist_fail.png）。

## §2 所見（重要度順）
1. 【中・分かりにくさ】「飛ばす」の意味が2画面で違う。QualifierNotice は押すと即・判の前へ抜ける（finish）が、FinalistAnnounce は押しても「以上の組が、決勝に進む。」の画面に飛ぶだけで、もう一度「つづける」が要る。同じ文言なので、押すと終わる・もう1回要る、が迷いの元（コード上の挙動・目視は読み上げ中のみ）。
2. 【中・要確認】知らせ（あった！／一覧で自組が光る／落選の「次いこ」）の直後に開演の儀→判→観客の声と、同じ結果をもう一度出す並び（準決勝は発表の後に判）。「通過」を2度驚かせる意図なら良いが、落選側は知らせで分かった後に重ねて判を見るので重く感じる恐れ。通しプレイでの体感確認が要る。
3. 【低・分かりにくさ】準々決勝の通知が「谷口：見た？」だけで、どの回戦の結果か通知の段では分からない（1〜3回戦は「1回戦の通過者を掲載しました」と出る）。直前の本番前カードで分かるので重くはない。直し案：通知に「準々決勝」を足す。
4. 【低・見た目】通過者一覧が出て「つづける」が出た後も、右上の「飛ばす」が残る。押す意味が無くなっているので消すか薄くしてよい。
5. 【低・分かりにくさ】ロック画面の通知は「通知をタップ」しか進め方が無い（画面のどこをタップしても進まない）。一覧の方は画面タップで早送りできるのと揃えるとよい。
6. 【低・フック】MZ_UI=gpresult／gploss の右上に DEBUG の「🏆優勝」「💪無双」札が出て、一覧の見出し近くに重なる。DEBUG 限定なので本編には出ない。gploss は名前どおり落選にならず1回戦を通過する（能力が足りてしまう）。落選の通し見本が要るなら別フックが要る。
