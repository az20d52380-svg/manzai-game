## §2 画面ごとの欠点

書体の注記：`Font.maru(n)` は既定 weight `.heavy` で、実体は **M PLUS Rounded 1c ExtraBold**（`Theme.swift:235-246`）。`.system(size:n, design:.serif)` は日本語だと **ヒラギノ明朝 ProN W3**（細い明朝）になる（スクショで確認）。週メインの台詞は `.system(13.5, weight:.medium)`＝**ヒラギノ角ゴ W5相当**（`WeekMainView.swift:371`）。
コントラスト比は WCAG 式の概算で、半透明は背景に合成してから出した（背景がグラデの所は中間色で概算）。

1. **暗い紫は「本番の言葉」**：地は #241C33→#2F2540（`ChoiceEventOverlay.swift:30-31`）。一方、StageScene と週メインは「日常パートは明るくポップ、暗転は本番系画面の語彙」と自分で決めている（`StageScene.swift:3-5`・`WeekMainView.swift:77`）。稽古場・楽屋・飲み会の日常イベントを本番の暗さで描いていて、**自分で決めた規則に反している**。
2. **読みにくさの正体はコントラスト比ではない**：地の文は 9.2:1 で数値は足りている。読みにくい原因は次の4つ。
   - 書体：細い明朝W3（`ChoiceEventOverlay.swift:73`／`:75`）。暗い地では横画がにじみ、13pt では一画が髪の毛ほどの細さになる。
   - 文字の大きさ：地の文13pt・台詞14pt（同上）。太さは週メインの台詞（13.5pt・W5）よりはっきり細く、地の文はさらに0.5pt小さい。読み物が主役の画面なのに、本作でいちばん細い本文になっている。
   - 1行の長さ：左右20pt（`ChoiceEventOverlay.swift:47`）＝本文の幅362pt で**1行約28字**。週メインの吹き出しは本文幅226pt で約16字（`WeekMainView.swift:373-374`）。ノベル系の読みやすい目安（1行20〜24字【仮】）を超えている。
   - 段落の塊：1つの台詞データに複数の文と手入れの `\n` が入っていて（ChoiceEventData の地の文）、自動折り返しと重なり「…受け取／ると、」「…言いかけ／て、やめた。」の**泣き別れ行**が出る（スクショ05_event_choice_live_w03）。
3. **会話部品がゼロ**：顔グラ・名前札・吹き出しがない。話者は10ptの金文字1行だけ（`ChoiceEventOverlay.swift:71-73`）。週メインは顔52pt＋白縁＋名前札（朱/青）＋白地の吹き出し（縁2.5pt＋ハード影）を持っている（`WeekMainView.swift:358-381`）。**同じゲームの中で、会話の見た目が2種類ある**。
4. **読み方の文法も2種類**：週メインの掛け合いは「1タップで1行を差し替え＋▼」（`WeekMainView.swift:342-356`）。イベントは「1タップで1つ下に追記して、全部を縦に積む」ログ方式（`ChoiceEventOverlay.swift:37-44`）。プレイヤーは画面ごとに読み方を覚え直すことになる。
5. **行が「ポン」と出る**：送りの `setupShown += 1`／`afterShown += 1` が `withAnimation` の外にあり、行に `.transition` もない（`ChoiceEventOverlay.swift:82`／`:84`）。そのため新しい行は0秒で現れる。1字ずつ出す演出・送りの効果音（`advance()` は無音）もない。
6. **送り合図が遠くて弱い**：「タップで進む」は 10pt・白40%・3.6:1 で、画面の最下部に固定されている（`ChoiceEventOverlay.swift:60`）。本文の末尾（上から約175〜425pt）から合図（約800pt）まで**視線が約380〜630pt跳ぶ**（スクショで実測）。▼も点滅もない。
7. **画面の下半分が空く**：本文は `ScrollView` の上詰め（`ChoiceEventOverlay.swift:35-48`）。短いイベント（0011・0013は3行）では画面の約7割が空になる。台詞窓を下に据える（ノベル型）か、絵で上を埋める必要がある。
8. **イベントの「始まった感」が無い**：出る時はシステム標準の下からのせり上がり（`WeekMainView.swift:85-96` の `fullScreenCover`）と効果音1つ（`ChoiceEventOverlay.swift:32`）だけ。小見出しは12ptの金文字1行（`:34`）で、札・帯・カットインがない。週メインには「第N週」の判がバネで出る部品がある（`WeekMainView.swift:208-219`）。
9. **ボタンに手応えがない**：選択肢と閉じるが `.buttonStyle(.plain)`（`ChoiceEventOverlay.swift:97`／`:112`）。押しても沈まず、クリック音もない（共通の `PressableStyle` は沈み0.95＋明るさ−10%＋カーソル音・`Theme.swift:253-269`）。選んだ時の振動もない。コード自身が掲げる「全タップに音」（`Theme.swift:266` のコメント）を破っている。
10. **選択肢が沈んで見える**：ボタンの地が白10%で、画面の地との差が約1.4:1（`ChoiceEventOverlay.swift:109`）。縁は金50%の1pt（`:110`）。週メインの行動カード（白地・色の縁3pt・ハード影＝`WeekMainView.swift:486-490`）と比べて「押せる物」に見えない。

### 2-5 イベントの場面ごとの欠点

- **選択前（05_event_choice_live_w03）**：setup が1行しかないイベント（「前夜の一本」「まだ敬語の残る間」「撮られる仕事」の3本）は、出た瞬間に本文全部と選択肢が同時に並ぶ（`ChoiceEventOverlay.swift:22`＝初期値1、`:49`）。読む前に選択肢が目に入るので、一拍の溜めがない。
- **選択直後（…_after）**：選んだ札が消えて、何を選んだかが画面に残らない（`ChoiceEventOverlay.swift:49-56` は `chosenID == nil` の間だけ描く）。さらに空欄だけが出る（§3 B-01）。
- **結果会話（…_result／…_close）**：選んだ結果（例：0020「まだ敬語の残る間」A＝相性+2・体力−15／B＝体力+10・メンタル+1。定義は `GameCore/Sources/GameCore/ChoiceEvent.swift:111-120`）は `applyEventChoice` で状態に入る（`GameSession.swift:507-512`）。しかし画面には何も出ない＝**状態のフィードバックが0**。週メインに戻っても、バーの伸び（`WeekMainView.swift:304`）と数字の跳ね（`:312`）は覆いの裏で終わっていて見えない。
- **地の文イベント（05_event_narration_w05）**：選択肢がないイベント（4本・`GameCore/Sources/GameCore/ChoiceEvent.swift:209-210`）は効果もない。それなのに、見た目は選択肢イベントと同じ暗い全画面で、週の獲得バーストを潰して割り込む（§3 B-02）。「彩りのひと幕」を、重い全画面ではなく週メインの掛け合い枠（banterBox）で軽く見せる手もある（§5）。
- **話者の顔の不足**：イベントの話者は 俺56・谷口52・先輩3・店長1・地の文21（ChoiceEventData を数えた）。`FaceCatalog.speaker` は俺と谷口しか持っておらず、先輩・店長は汎用の灰色の襟になる（`CharacterAvatars.swift:139-145`）。名前札の色も「谷口以外は青」（`WeekMainView.swift:368`）なので、そのまま流用すると**先輩が俺と同じ青**になる。

### 3-1 B-02 の詳細（獲得バーストが覆われる）

コードから組んだタイムライン（`WeekMainView.swift`）：

1. t=0 カードをタップ。Beat1 の一言を出す（このカードを直近4週に使っていなければ・`:424-430`）。
2. t=0.12（一言ありなら +0.7＝0.82）秒で `burstGen += 1`・`burstHold = true` を立ててから `session.choose`（`:433-438`）。週送りの中の `pump()` が、イベントの発火を判定して `pendingChoiceEvent` を立てる（`GameSession.swift:841-848`→`:359-`）。
3. Beat2 のタスク：チップを **1.2秒** 見せ（`:143`）、0.25秒で退場（`:146`）、`defer` で `burstHold` を下ろす（`:127`）。ここで覆い（システム標準のせり上がり）が出始める（`:85-90`）。
4. 実力・相性バーのオレンジの重ね表示（`gainsVisible`）も同じ1.2秒で消える（`:115-119`）。覆いを閉じた後には、この週に何が伸びたかの痕跡が何も残らない。

**設計そのものの問題（確定）**：うまく動いても、獲得の見える時間は最大1.2秒。そのあとすぐ暗い全画面が来て、獲得の記憶を上書きする。週メインで唯一の「効いた！」の一拍が、イベントのある週に限って一番弱くなる。

**保留が早く外れる経路（要実機確認・疑わしい順）**：
- (a) チップが空の週は、保留が即座に外れる（`:132-136`→`defer`）。実力が伸びない（器が満ちた後など＝`:541` の判定が0）・相性の伸びが四捨五入で0（`:545`）・ネタの変化なし・体力差0、が重なる週はこの経路を通る。
- (b) `try? await Task.sleep` が取り消しを握りつぶす（`:143`／`:146`）。Beat2 のタスクが何かの理由で取り消されると、待たずに末尾まで走り、即座に `defer` が保留を下ろす。取り消しの種は `.task(id: session.week)` の付け直し、または RootView の `switch session.phase`（`RootView.swift:178-180`）で週メインの識別子が作り直されること。
- (c) リード観測の「直後0.5秒」と設計値（タップから0.82秒後に週送り→さらに1.45秒保留）が合わない。実機で `choose` の時刻・`burstHold` の下りた時刻・覆いの出た時刻を記録して確定させる（ログ追加だけで済む）。
- (d) 付随の疑い：`fullScreenCover` を閉じて週メインに戻った時に、`.task(id:)` が再実行されるかもしれない。その場合「第N週」の判（`:148-154`）と週めくり音が二度鳴る。要実機確認。
