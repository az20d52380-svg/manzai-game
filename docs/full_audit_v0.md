## 2. 【設計上の懸念】（★の理由）

- **G-03 セーブ形式**：出荷した瞬間、`manzai.save.v1` の JSON 形は"既に端末にある契約"になる。今のまま出すと、最初のアップデートで GameState に非Optional のフィールドを1つ足しただけで、進行中の全プレイヤーのセーブが黙って消える（`try?` が失敗を握り潰す）。版数と Optional 規約は**出荷前にしか安く入らない**。
- **G-11 バンドルID**：App Store Connect のアプリレコードはバンドルIDに紐づき、作成後は変更できない。`com.manzaigame.mvp` のまま作ると"mvp"が永久に残り、本編を同じアプリで出す前提（H-02/H-07）とも食い違う。
- **H-02 業態**：無料で出したアプリを後から有料化すると、既存ユーザーの扱いとレビューで揉める。逆（有料→無料、無料→IAP追加）は通常の手順で済む。**最初は「後から足せる側」に置く**のが後戻りの安い選択。決定はオーナー（規律C-8）。
- **H-06 アプリ名**：名前は更新で変えられるが、商標衝突が出荷後に見つかると強制改名になり、レビューと検索の蓄積を失う。実査は申請前の0.5h【仮】で済む。

## 3. 既決への異議（1件だけ）

**対象**：「『ほぼ優勝できない』初回体験は意図的な仕様」×「10年キャリアは1年MVPの外」の**組み合わせ**。

- **事実**：この決定は10年キャリア前提で作られている（`endgame_design_v0` の検証値は決勝到達17〜28%・1年目優勝0%）。1年MVPに切り出すと、"ほぼ"は**構造的に不可**へ変わる（§0・H-01 の机上上限【仮】）。勝てないのではなく、**決勝の舞台に立てない**。
- **帰結**：作品の看板である決勝演出（7審査員の一斉オープン・票札めくり）と勇退ED、計715行が出荷版の誰にも見られない。「誰に負けたか」を見せる設計（`finals_direction_v0` §4-D）も1年版では発動しない。悔しさの対象が画面に存在しないため、負けは"悔しさ"でなく"上限の壁"として届く。
- **異議の中身**：決定（ほぼ優勝できない／10年は外）は**覆さない**。覆さずに、1年版でも決勝を"観せる"手当て（H-01：観客版決勝、代案は年次リザルトの1枚）を**出荷条件に入れる**べき、という異議。数値（ライン・予算）は動かさない。
- **やらないこと**：1年版専用にGPラインを下げる（規律B-5・sim前提の喪失）、3年MVP化（3年目末でも実力値は約21【仮】＝`CareerGoldenTests.swift:85-86` で届かない）。
