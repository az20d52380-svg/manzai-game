# 10年遊んだ時のファンレポ（ヒトコエの観客の一言）の読み返し率の実測 v0

懸念の台帳 L39「ファンレポの枯渇」の実測。15c9de0 で 54→161本に増補した後の状態（2026-10-25）。材料のみ・コード不変・決定はオーナー。

## §1 要点3行
1. **10年で約330〜340本読み、うち約63〜67%が「前に読んだ同じ文」**（steady 62.7%・strong 66.7%。1〜3年目 19%→4〜6年目 75〜82%→7〜10年目 85〜92%）。161本に増やしても、3年目以降は読み返しが主になる。
2. 偏りの原因は**通過・点差8以上の「熱狂（A帯）」24本**（知名度が育つと26本）。強いコンビの読みの約65〜70%がここに集中し、A帯の読み返しは88〜89%（1キャリアで同じ文を平均9回前後）。他のプールは、強いコンビが読む量が少ないので 0〜30%に収まる。
3. 負けが続く型（poor）では**不発・重い空気（D帯）23本が最も薄く**、読み返し69%・C帯32%。ただしこの型は約6.4年で終わる。

## §2 手法と近似
- 実測コード：scratchpad `fr/` の Swift 実行パッケージ（GameCore にパス依存・コミットしない）。`FanReportData.swift`（アプリ本物。プールを読むため `private` を外しただけの写し）をリンクし、**`FanReportData.voices` をアプリと同じ引数で呼ぶ**。
- 先例（banter_repeat_measure_1025_v0 と同じ `WeekRunner` 10年通し・ボット3種）：steady（8手周期・各年頭に能力下限35）／strong（1〜3年目35・4年目から60）／poor（バイト中心・約6.4年で終了）。大会は常に夜行バス。tools の Python sim ではなく Swift の `WeekRunner` を使った（ファンレポの文プールが Swift にしか無く、`margin`/`burst` は `StageResult` から取れるため。先例と同じ）。
- アプリ側の選び方（TournamentResultView.swift:52-61、GameSession.swift:127-134、FanReportData.swift:241-267）を写した：
  - 呼ぶ単位＝結果画面1回（`summary.results` の `isStage` の最後の1件）。`salt = 年*131+週`。**乱数は使わない**（salt の剰余と「このキャリアで出した声」`usedFanLines`＝古い順・上限600の再現）。同じ `salt` の再描画はキャッシュ＝1回しか数えない。
  - 帯：通過＝margin≥8でA／それ以外B。敗退＝margin≥-3でC／-3〜-10はsaltの偶奇でC・D／それ以下はD。`burst` なら先頭にハマった夜の文。同帯→隣の帯（A↔B・C↔D）の未使用の順、尽きたら使用済みを古い順。5回に1回、最後の1枚をミスリード枠（misPass/misFail）に差し替え。
  - `knownOnly` の絞り込み＝`isKnown(year, fame)`（2年目以降かつ知名度15以上）が偽の間は除外。ボットの `fame` は `WeekRunner.state.fame` を使用（本物）。
- 数え方：コンビ名は固定（「ナナ」）。表示された文を全て「読んだ」と数える（タップ送りで全枚読む前提＝実際は途中で飛ばされることもある）。読み返し率＝（読んだ本数−異なる文数）／読んだ本数。プール別は文の出所のプール（隣の帯から借りた文は借りた先のプールで数える。複数プールにある文は先頭の所属＝burst>A>B>C>D>misPass>misFail）。
- **近似・限界**：①ボットは強く、10年で結果画面を約108〜110回見る（1年約11回）。実プレイでこれより少ない人は、読み返し率は下がる。②タップで飛ばす・「次の声へ」で全部は読まない人も同様。③GP決勝・敗者復活も同じ結果画面として数えた。④セーブ再開・500枚超のログ切り捨ては無視（上限600は再現）。
- 本数：n=300で当たり→n=1000で確認（差は±0.1〜1pt）。以下は n=1000。

## §4 最も薄いプール
- **A帯（熱狂・通過点差8以上）**：量が最も集中する。24〜26本に年約22〜23回当たるため、4年目には全文を一巡し、以降は平均9回前後同じ文を読む。1キャリアで26本すべて読み切る（異なる文＝26.0）。
- **D帯（不発）**：負けが続く型で最薄。23〜24本に年約12回当たり、2〜3年で一巡（読み返し69%）。強い型では読む量が少なく0.3〜20%。
- **C帯**：poor型で32%。steady で9%、strong で1%。
- 余裕があるのは burst（読み返し0%）・B・misFail（0〜24%）。当たり外し通過側は12本で、strong 型で30%。

## §5 増やすならどこか（選択肢の材料。決定はオーナー）
- 案1：A帯を増やす（強い型の読みの約65〜70%が集中）。ここが26本から2倍の約50本になれば、10年で読み返し率が推定で半分近く。増やす文は「熱狂」だけでよい（点差8以上の通過）。
- 案2：A帯を点差で2段に分ける（例：8〜15と15以上）。プールを割ると各段の文は薄まるので、増やすのと併用。
- 案3：D帯・C帯を増やす（負けが続く型向け）。型によっては約6年で終わるので優先度は低い。
- 案4：何もしない（1〜3年目は19%で低い。3年目以降の反復は「通ってるファンの口癖」と読める）。
- 案5：A帯を通過回数で段階的に出す（例：初回の通過だけ別プール）など、出し方を変える。
- 注意：実プレイの結果画面数が測定より少ない可能性（§2）。実プレイの記録が取れればそれで補正できる。

## 追補：増補分（15c9de0）の文面の点検（10/25 夜・定期の回・親）
