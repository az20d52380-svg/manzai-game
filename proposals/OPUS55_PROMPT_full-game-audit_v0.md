# manzai-game 全体監査依頼 — 改善点を大量に、ただし全部に値札を付けて

あなたには iOS/SwiftUI の個人開発ゲーム **manzai-game**（架空の漫才賞レースを舞台にしたコンビ育成SLG）を
**全体監査**してもらいたい。欲しいのは**改善点の大量のリスト**。ただし条件がある——
**1件も「値札」なしで出さないこと**（詳細は §4 の出力規格）。

## 0. このプロジェクトの既往症（監査方針に直結するので先に読む）

このプロジェクトは **設計ドキュメント109本・提案57本に対し、動いているSwiftは約9,400行**という比率で、
**「設計しすぎて出荷が遅れる」**という自己診断を既に下している（`docs/game_reality_check_v0.md`）。

したがって——

- **追加の設計書を書くことは、このプロジェクトでは害**。あなたの成果物は「もっと詳しい設計」ではなく
  **「直す/直さない/後回しの判断が付いた指摘リスト」**でなければならない。
- 「〜を検討すべき」「〜の設計が必要」という結語は**禁止**。必ず「どう直すか」まで書く。
- 改善案が新しいシステムの新設を要求する場合は、**それが新設である事実を明示**し、
  既存機構の転用で済む代案を必ず併記する。

## 2. 絶対制約（破ると壊れる）

1. **コードを一切書かない・ファイルを編集しない**。`ManzaiGame/` `GameCore/` `tools/` は読むだけ。
2. **git操作をしない**（commit / push / branch / merge / add 全面禁止）。読み取り専用の `cat` / `git show` / `git log` のみ可。
3. **固有名（大会名・芸人名・事務所名・審査員名・番組名）は全て架空のまま**。実在の賞レース・団体・芸人名を一切出さない。
   「似顔絵・決めゼリフ・経歴の雰囲気を実在に寄せる」案も禁止——法務一次まとめ（`docs/legal_risk_v0.md` §4）の結論は
   **「氏名を避けるだけでは不十分、"同定要素の総体"の架空化が必要」**。
4. **バランス数式・乱数消費順（golden）には触れない**。触る提案をする場合は
   **「規律A発動＝golden全再測が必要」と値札に明記するに留め**、実測や数値確定はしない。
5. **数値は全て【仮】と明記**。断定しない。
6. **ネタ本文（ボケ/フリ/オチ/パンチライン）は一文字も書かない**——これは作品の一線。
   笑いは地の文にのみ宿らせる設計（`.claude/skills/manzai-drama-voice/`）。
7. 進め方の規律：**質問は1論点ずつ／選択肢には推奨理由を添える／後戻り困難な判断は【設計上の懸念】と明記**。

## 4. 出力規格（ここが本依頼の核心）

### 4-1. 指摘は全てこの1行フォーマットで出す

```
| ID | レンズ | 症状（何が起きている） | なぜ悪い（根拠） | どう直す（具体） | 工数【仮】 | 出荷判定 | golden影響 | 不可逆 |
```

- **ID**: `A-01` のようにレンズ記号＋連番。
- **根拠**: 「一般にUXでは」ではなく、**このゲームの何を見てそう言うか**を書く（ファイル名・行・画面名・docの§）。
- **どう直す**: 「検討する」禁止。触るファイル名まで指す。
- **工数【仮】**: 時間単位（例 `2h` / `1.5d`）。全て【仮】。
- **出荷判定**: `BLOCKER`（直さないと初見が離脱/壊れる） / `SHOULD`（出す前にやれると良い） / `AFTER`（リリース後）。
- **golden影響**: `なし` / `規律A発動（golden全再測）`。
- **不可逆**: 後戻りが困難なら `★`。★を付けたものは本文で【設計上の懸念】として理由を書く。

### 4-2. 件数と配分

- **総数は最低40件、上限なし**（大量に欲しい）。レンズA〜Hのどれも**最低3件**は出す。
- ただし **`BLOCKER` は最大8件まで**に絞る。全部をブロッカーにするのは監査ではなく悲鳴なので、
  **「これを直さずに出すと初見が離脱する/アプリが壊れる」だけ**をブロッカーにする。
- 既に正しく出来ている点も **「良かった点」として最低5件**挙げる（削ってはいけない場所の特定も監査の仕事）。

### 4-3. 最後に1枚のロードマップ

1. **今すぐやる（リリース前・BLOCKERと一部SHOULD）** — 着手順に並べ、各行に工数【仮】と「完了の定義」を付ける
2. **やらない（CUT）** — 理由つき。「やらない」と言い切るのを恐れないこと
3. **後回し（リリース後アップデート）** — いつ・なぜ後なのか
4. **合計日数【仮】** と、その順番で進めた場合に**最初に遊べる形になるのはどこか**

## 5. 既に決着している論点（蒸し返さないこと）

以下はオーナーが既に決めている。**再提案しない**（ただし「決定が間違っている」と考える場合は、
理由を添えて**1件だけ**異議として出してよい）。

- **型×審査員の相性を合否スコアに乗せる（1-b）＝ 試遊後に判断で据置**（golden全再測が代償のため）
- **会話は「常時＝俺の内心モノローグ・ボケない／相方の掛け合いはレアイベント限定」** という配分
- **ネタの型は年単位の選択ではなく、ネタ1本が持つ属性**
- **周回メタ（トロフィー/ガチャ）と10年キャリアは1年MVPの外**
- **バランス数値は全て【仮】・体感の問題を数値で直さない**（まず演出・頻度・テキストで解く）
- **「ほぼ優勝できない」初回体験は意図的な仕様**（バグでも調整漏れでもない）
